# GWD Architecture

This document describes the target structure of the project, where the code is today, and how far the cleanup has come. File and line references were checked at commit `257afbc`.

The detailed plan (`PLAN.md`) and the list of all findings (`BEFUNDE.md`), both in German, were in the working folder `docs/aufraeumen/` until P7.4 removed it. IDs such as `EVAL-1` refer to that findings list. Both files stay in the Git history: `git log --diff-filter=D --oneline -- docs/aufraeumen` names the commit that removed them, and `git show <commit>^:docs/aufraeumen/BEFUNDE.md` prints the list. Step IDs such as `P5.8` are the rows of the step checklist at the end of this document.

**Work order for AI assistants:** "Run step Px.y. Change only the named files." The rules are in [AGENTS.md](../AGENTS.md).

## Purpose

GWD trains a CNN to detect gravitational wave chirps in noise and evaluates it with ROC metrics. It also includes interactive learning apps. There is currently no valid Matched Filter baseline (see D5).

The workflow is: fetch noise → generate data → validate → train → evaluate → optimize thresholds → compare models.

## Components

The target is one installable package, `gwd`, in `src/gwd/` (D8).

| Component | Target | Responsibility |
|---|---|---|
| config | `src/gwd/config.py` | Project root, paths, and constants. Nothing happens on import; writers call `ensure_dirs()` first. |
| core | `src/gwd/core/` | Physics: waveforms, noise, SNR, interferometer learning model, time domain simulator. No file or network access. |
| data | `src/gwd/data/` | Scenarios, the one injection, the one filter chain, GWOSC access, dataset writing, provenance (manifest), and validation. |
| registry | `src/gwd/registry.py` | The one place that finds, selects, and loads models. Metadata and per-model thresholds. |
| training | `src/gwd/training/` | Model definition and training. |
| evaluation | `src/gwd/evaluation/` | Fixed test sets, metrics, thresholds, comparison, leaderboard. |
| apps | `src/gwd/apps/` | GUI, interaction, and audio only. No physics, injection, filtering, or model search of their own. |
| cli | `src/gwd/cli.py`, `src/gwd/env.py`, `main.py` | Dispatch only. `main.py` is a thin menu. |

`core/interferometer.py` and `core/simulation.py` stay in core on purpose. Whether app-specific physics belongs there is a design question (`APP-14`), and the import rules below keep the boundary.

Before the cleanup, the scripts in `src/` found each other through `sys.path` edits with generic top-level names such as `config` and `utils` (`hygiene:HYG-M5`). Since P2.1, tests and scripts both import `gwd.core` (`CORE-5`). From P2.3 to P2.6, the root `config.py` was only a shim for `gwd.config`. Since P2.4, `gwd.data` and `gwd.training` use absolute imports without `sys.path` edits and run with `python -m`, for example `python -m gwd.data.generate`. Since P2.5, all code is in `src/gwd/`: evaluation, apps, and `gwd.data.preprocessing` import absolutely, `src/utils/` is gone, and `src/gwd` has no `sys.path` edits. Since P2.6, the root `config.py` shim and the pytest `pythonpath` entries (`src` and `.`) are gone. Tests import the installed `gwd` package (editable in `.venv`, `pip install -e` in CI), so the old top-level names `config`, `utils`, `dataset`, and `gwd_core` no longer resolve.

**Model registry (since P3.3).** `gwd.registry` is the only model search. `list_models()` returns the `.keras` files in `models_registry/`, oldest first, ordered by the timestamp in the name `gwd_model_YYYYMMDD-HHMMSS`. Before P3.3 the four copies chose by ctime, which changes on chmod, copy, or restore under Linux and WSL (`apps:APPX-4`). On the laptop, ctime picked `gwd_model_20251124-234359` as the newest; the name picks `gwd_model_20251205-232013`. Names without a valid timestamp fall back to mtime with a warning. `resolve()` turns `latest`, a model name, or a path into a file, and `load_model()` imports TensorFlow lazily and loads with `compile=False`, which also avoids Keras' optimizer warning. `read_metadata()` and `write_metadata()` handle the `.json` file next to a model; training names its `.json` with `metadata_path()` since P3.7 and writes it through `write_metadata()` since P4.1. `gwd eval run` and `gwd eval thresholds` take `--model` (default `latest`), and `gwd eval compare` takes it repeatedly (default: all models). The Glitch Hunter loads its model through the registry too (`--model`, default `latest`); since P4.4 it starts without one, with 'Ask AI' off (`APP-8`). Since P4.1 it also reads the model's metadata and warns, on the console and in red above the plots, if the real noise share of its training data was 0 (`apps:APPX-1`); for metadata without the share (all models trained before P4.1) it prints a note that it is unknown. No evaluation module and no app imports TensorFlow itself: `tests/test_architecture.py` checks the source, and `tests/test_registry.py` checks at runtime that `run()` of the three evaluation modules handles an unknown model with exit code 1 without loading TensorFlow.

**Command line (since P3.6).** `gwd` (`[project.scripts] gwd = "gwd.cli:main"`) is the one entry point (D8):

| Command | Runs |
|---|---|
| `gwd data fetch-noise [--detector --gps --duration]` | `gwd.data.fetch_noise.fetch_and_slice` (network; overwrites chunks of the same name in `data/noise_background/`) |
| `gwd data generate [--n --seed --out --scenario --overwrite]` | `gwd.data.generate.generate_dataset`; `--scenario` is `train_v1` (default), `eval_v1`, or `app_v1`, since P6.2 `train_v2`, `indist_v2`, `stress_v2`, or `app_v2`, and since P6.6 `train_v3`, `indist_v3`, `stress_v3`, or `app_v3`; a folder that is not empty needs `--overwrite` |
| `gwd data validate [--data --plots]` | `gwd.data.validate.run`; `--plots` with or without a folder writes the report plots, which are off by default |
| `gwd train [--data --epochs --batch-size --lr --patience --mixed-precision --deterministic --seed]` | `gwd.training.train.train(TrainConfig(...))` with only the options that were given; without `--seed` a seed is drawn (P5.6) |
| `gwd eval build-testset [--testset --scenario --seed --n --rebuild]` | `gwd.evaluation.testsets.build` (since P5.7): draws a fixed test set once, or loads and checks it; `--scenario` is the plan's name for `--testset` |
| `gwd eval run [--model --real/--no-real --testset --seed --n]` | `gwd.evaluation.evaluate.run`; since P4.3 `--no-real` is the default and `--real` adds the field test (network, D10); since P5.7 on a fixed test set; since P5.8 at the model's threshold, with a row in leaderboard v2 |
| `gwd eval thresholds [--model --save/--no-save --testset --seed --n]` | `gwd.evaluation.thresholds.run`; saves by default and never asks (`EVAL-17`); since P5.8 it calibrates on `calib_bg` and saves to the model's metadata |
| `gwd eval compare [--model ... --testset --seed --n]` | `gwd.evaluation.compare.run` |
| `gwd eval leaderboard` | `gwd.evaluation.leaderboard.show`; since P5.8 leaderboard v2, one table per test set |
| `gwd app waveform\|interferometer` | the app module's `__main__` block, through `runpy` |
| `gwd app glitch-hunter --model latest` | `gwd.apps.glitch_hunter.app.main(model)` (since P4.4); `--model` defaults to `latest`, and with another app it exits with 2 |
| `gwd env` | `gwd.env.main`: versions, extras, waveform backend with the PyCBC version, resolved paths, matplotlib backend and whether it can open a window |

`gwd.cli` holds only dispatch. Each handler imports its module when it runs, so `gwd --help` and `build_parser()` load no numpy, and `gwd data generate` loads neither TensorFlow nor gwpy (`tests/test_cli.py`). For the `eval` commands, `--testset`, `--seed`, and `--n` name a fixed test set (since P5.7; defaults `DEFAULT_TESTSET`, `TESTSET_SEED`, and `TESTSET_SIZE` in `gwd.config`, filled in by the functions, so the parser still imports no `gwd.config`); the set draws from its own random stream, and `seed_everything`, which seeded Python's `random` and the global numpy RNG until P5.7, is gone. Since P4.1, `gwd data generate` passes the seed to `generate_dataset(seed=...)`, which draws from `np.random.RandomState(seed)` (the same samples as the seeded global RNG), and `gwd train` passes it in `TrainConfig.seed`, which `train()` sets with `tf.keras.utils.set_random_seed` (Python, numpy, and TensorFlow) and gives to the split; both record it. Without `--seed`, `gwd data generate` is unseeded, as before; since P5.6 `gwd train` draws a seed instead, prints it, and records it with `seed_drawn: true`. Since P5.3 `gwd.core` draws only from an `rng` it is given; `gwd.data.injection` passes on its own `rng`, which defaults to the global `np.random`; since P5.7 the test sets pass theirs. Exit codes: 0 on success, 1 when a command fails (since P5.2 also a missing PyCBC for a command that draws waveforms; since P5.7 a cached test set that does not match its hash or is stale; unknown or missing model, missing or broken dataset, a dataset with validation findings, an output folder that is not empty, rejected or failed download, no model to compare), 2 for invalid arguments and (since P4.5) for an app that cannot open a window, 130 on Ctrl+C. Since P4.1, `gwd train` checks for `labels.csv` before it imports TensorFlow and reports a missing dataset in one line on stderr instead of a traceback; `gwd data fetch-noise` reports any download error on stderr (`DATA-6`, `tests/data/test_fetch_noise.py` lets gwpy's `fetch_open_data` raise). The modules no longer parse options: `evaluate`, `thresholds`, `compare`, `validate`, `fetch_noise`, and (since P3.7) `train` still run with `python -m` and their defaults, and stop with a pointer to `gwd` if given options. `gwd env` checks packages with `find_spec` and their metadata and imports only PyCBC, through `gwd.core.waveforms.pycbc_available()`, because only that import shows whether PyCBC works; since P5.2 it shows the backend of the pipeline (`pycbc <version>`, or `MISSING`) and of the demo apps (until P6.1 `pycbc` or `newton`; since then `pycbc <version>`, or that the waveform explorer stops and the Glitch Hunter has real data only). Since P6.1 PyCBC is a base dependency, so the extras list has no `physics`. The smoke tests run every pipeline stage and app as a `gwd` command line (`tests/smoke/entrypoints.py`); the `python -c` drivers that set module globals and stubbed the field test are gone. Since P7.4 the pipeline stages run in the end-to-end test `tests/test_e2e.py` (see Step checklist), and `tests/smoke/` only starts the apps.

**Training (since P3.7).** `gwd.training.model.build_model(input_shape, learning_rate=LEARNING_RATE)` builds and compiles the CNN and changes no global state. Its architecture is unchanged and fixed at 1 074 609 parameters by `tests/training/test_model.py`; a new one is a deliberate change (`DATA-26`). `gwd.training.train.train(cfg)` runs one training. `TrainConfig` holds the dataset, model, and plot folders, `epochs`, `batch_size`, `learning_rate`, `patience`, and `mixed_precision`. The defaults are `EPOCHS`, `BATCH_SIZE`, `LEARNING_RATE`, and `EARLY_STOPPING_PATIENCE` in `gwd.config`, which also holds `REDUCE_LR_PATIENCE`, `VAL_SPLIT`, and `TEST_SPLIT`; the values are those hard-coded before, except the split (see below). Importing the module changes nothing (`DATA-13`): `new_run()` creates the timestamp, the name `gwd_model_YYYYMMDD-HHMMSS`, and the paths when `train()` runs, and the plot uses a matplotlib `Figure` without pyplot. Mixed precision follows D7: `choose_precision()` takes `mixed_float16` if TensorFlow finds a GPU or `--mixed-precision` is set, else float32. Before P3.7, the import set `mixed_float16` everywhere, so CPU and CI runs now train in float32; on a GPU nothing changes. `train()` prints the policy, sets it only for the run, restores the previous one, and records it as `precision_policy` in the `.json`, together with `learning_rate` and `early_stopping_patience`. Since P4.1 the `.json` also has `epochs_trained` (early stopping can end before `epochs`, the maximum), `best_epoch` (1-based, the saved weights), `seed` (null if unseeded), and from the dataset's `manifest.json` its SHA-256 (`dataset_manifest_sha256`), `dataset_scenario`, `waveform_backend`, and `real_noise_fraction`; without a manifest these four are `unknown (v1)` (`DATA-20`). The `gwd train` handler sets `TF_CPP_MIN_LOG_LEVEL=2` and `TF_ENABLE_ONEDNN_OPTS=0` with `setdefault` before it imports TensorFlow, as the module did on import before; values from the caller now win. (After P7.4 every handler that loads TensorFlow does this, with level 3; see "Evaluation output per model" below.) `python -m gwd.training.train` still runs the defaults, but without those two variables.

**Training split, seeds, and metadata (since P5.6).** `gwd.training.split.split_dataset(labels, seed)` splits `labels.csv` into train, val, and test, 70/15/15 (`VAL_SPLIT` = `TEST_SPLIT` = 0.15; before, `TEST_SPLIT` = 0.2 was the validation and the test data at once, `DATA-2`, `EVAL-25`). A group is the `noise_file` of a sample; a sample with Gaussian noise is a group of its own. The groups are assigned greedily, the largest first and ties in the order of `np.random.default_rng(seed)`, each to the part that is furthest behind its share of the strata `has_signal` × `noise_source`, so each part is stratified by class and noise source and no real noise chunk is in two parts (`evaluation:MISS-4`). sklearn's `GroupShuffleSplit`, which the plan named, does not stratify and is not used. A dataset without the `noise_file` column (before P4.1) is split by sample and stratified by class, with a warning on stderr that recommends generating it again; the metadata then has `split_grouped: false`. A part that would stay empty raises `ValueError`. The module uses only numpy and pandas. `train()` seeds every run (`DATA-5`, `hygiene:HYG-M2`): `TrainConfig.seed`, or `draw_seed()` (a random integer below 2³² from `secrets`) without one, goes to `tf.keras.utils.set_random_seed` and to the split and is printed in a `Seed:` line. `TrainConfig.deterministic` (`--deterministic`) also calls `tf.config.experimental.enable_op_determinism()`, which stays on for the rest of the process; the same seed then gives the same val_loss on the CPU (checked there only; a GPU does not guarantee it). The val part steers `EarlyStopping`, `ModelCheckpoint`, and `ReduceLROnPlateau`; the test part is evaluated exactly once, with the best epoch from the checkpoint, after training. `load_data()` returns `LoadedData(X, y, labels, sha256)`: `X` is one preallocated float32 array, each sample z-scored in float64 first, so float64 datasets from before P5.6 are read the same way (`DATA-21`); `sha256` hashes the bytes of `labels.csv`, then the dtype and raw data of every sample in its order, in the same pass. The `.json` gains `dataset_hash` (that hash), `seed` (the seed used), `seed_drawn`, `deterministic`, `split_grouped`, `split` (`val_fraction`, `test_fraction`, `grouped_by`, `groups`, and the sizes `train`, `val`, `test`), `val_accuracy` and `val_loss` of the best epoch, and `test_accuracy` and `test_loss` (`DATA-20`); `metrics` keeps the values of the last epoch. `test_split` and `metrics.test_set_accuracy` are gone; neither the leaderboard nor anything else read them. Old models and their `.json` stay usable; new models are new files. The plan's optional archive without the optimizer state is not done: Keras 3 ignores `include_optimizer=False` for `.keras` files. `tests/training/test_split.py` checks sizes and class balance within ±2 % per part, that no chunk is in two parts, the warning without the column, and the seed; `tests/training/test_train.py` checks the float32 loading of float32 and float64 files, the hash, the metadata, and (slow) that two runs with the same seed and `deterministic` give the same val_loss.

**Evaluation metrics (since P4.2).** `gwd.evaluation.metrics` holds the metrics and threshold strategies as pure functions: labels and scores in, numbers out. Importing it loads neither matplotlib nor TensorFlow. `find_optimal_thresholds` moved there from `thresholds.py` and was fixed, not rewritten. Fixed FPR (5% and 1%) takes the highest TPR with FPR ≤ target, ties going to the lower FPR, and fixed TPR (90%) the lowest FPR with TPR ≥ target; before, both took the ROC point nearest to the target, which could lie beyond it (`EVAL-16`). No strategy picks the infinite first threshold of `roc_curve`, which `json` would write as the invalid `Infinity`; if no finite point meets an FPR limit, the threshold lies just above the highest score and detects nothing. F1 comes vectorized from `precision_recall_curve` (`f1_curve`) instead of one `f1_score` call per threshold, and its TPR and FPR are computed at its own threshold instead of the nearest ROC threshold. So the recommended thresholds in `results/optimal_thresholds.json` changed; since P5.8 they are only a reference (see Thresholds below). `predict_labels` is the one detection rule, score ≥ threshold, as in `roc_curve`. The operating point, the sensitivity curve, and the confusion matrix of `gwd eval run` use it; the latter two counted score > threshold before (`EVAL-15`). Since P4.3 the field test uses the same rule; the threshold was 0.15 until P5.8. `snr_at_rate` finds SNR50 and SNR90 without the bare `except` and keeps 0.0 as a valid value, which the plot and the metrics box showed as missing before (`EVAL-22`). The metrics box shows formatted values instead of raw floats and no longer has the "False Alarms" line, which repeated the FPR; the `far` value is gone from the result, and the leaderboard never read it. `gwd eval compare` loads the models one after another, computes each ROC curve once, and gives each model one color in both panels, by sorted name; before, the bars took their colors in AUC order and the curves in load order. It writes `plot_compare_roc_<timestamp>.png` and `plot_compare_roc_<timestamp>_zoom.png`; before, the zoom overwrote the comparison plot (`EVAL-18`, `HYG-24`). The test sets were still drawn anew from `EVAL_V1` in every command until P5.7 (see Test sets below). `tests/evaluation/test_metrics.py` and `tests/evaluation/test_compare.py` check this; the second uses stub models, so it also runs in CI (`EVAL-20`).

**Test sets (since P5.7).** `gwd.evaluation.testsets.build(name, n, seed)` draws a named test set once and loads it afterwards (`EVAL-10`, `core:MISS-3`, `hygiene:HYG-M2`). The sets are `EvalSet`s in `gwd.data.scenarios.TESTSETS` (D4 = A), so the parser can list them without numpy: `indist_v1` draws from `TRAIN_V1` with its noise mix (80 % real if `data/noise_background/` has chunks), `stress_v1` from `EVAL_V1`; `gwd eval run`, `thresholds`, and `compare` default to `stress_v1`, seed 0, n 1000 (`DEFAULT_TESTSET`, `TESTSET_SEED`, `TESTSET_SIZE` in `gwd.config`). Each set has a balanced part `test` (even indices signal) and a noise-only part `calib_bg` of the same size, on which `gwd eval thresholds` calibrates the thresholds since P5.8. The k-th signal sample of `test` draws its peak SNR uniform within bin k mod (number of bins) of `EvalSet.peak_snr_edges()` (width 1 for `indist_v1`, 0.25 for `stress_v1`), so the peak SNR stays uniform and every bin is filled. Each part draws from `RandomState(MT19937(SeedSequence(seed, spawn_key=(0x67776474, crc32(name), part))))`; training seeds MT19937 with the plain integer or uses `SeedSequence(seed)` without a spawn key, so the streams are disjoint, and nothing touches the global numpy RNG. The samples are z-scored with `normalize` (default eps, as in training) and stored as float32 with their parameters in `data/eval/<name>_<seed>_<n>.npz` (`TESTSET_DIR`); the manifest goes to `results/testsets/<name>_<seed>_<n>.json` (`TESTSET_MANIFEST_DIR`, D9 = A: both local, ignored by Git). It holds the format (`TESTSET_FORMAT` = 1), name, scenario and `Scenario.hash()`, seed, n, the stream, `time_axis`, waveform backend, the scenario fields, the training reference, the noise folder and a fingerprint of its chunks (count, and a SHA-256 of their names and bytes; null for a scenario without real noise), the noise sources per part, the bins, the versions, Git commit, the parameters of every sample, and `sha256`. That hash covers a header (format, name, scenario and its hash, seed, n) and every array with name, dtype, and shape, not the npz bytes, whose zip entries carry the time of writing. `load()` recomputes it and raises `InvalidTestsetError`, a `ValueError`, if it differs (an array was changed), or if the manifest is stale (another format or scenario hash, or other noise chunks); `build()` never replaces a cached set on its own, only with `rebuild=True` (`--rebuild`). A missing npz or manifest means a new build. A cached set loads without PyCBC. With real noise, the hash is reproducible only with the same chunks; tests and CI build with an empty noise folder (Gaussian only). On the laptop, with the 1024 local chunks, `indist_v1` (seed 0, n 1000) has 801 real and 199 white noise samples in `test` and gave the same SHA-256 in two fresh `GWD_HOME`s. The real chunks of `indist_v1` can be ones the training data used, until P6.3.

`gwd eval run` scores `test` once: ROC, AP, operating point, and the efficiency curve, the detection rate of the signal samples per peak SNR bin (`efficiency_curve`), with SNR50 and SNR90 at the first bin center that reaches the rate and the mean optimal SNR of that bin (the 15 extra levels of the old sensitivity curve are gone, so SNR50 and SNR90 are not comparable with older rows). `binned_metrics` adds, through `signal_bin_metrics` and `group_metrics` of `gwd.evaluation.metrics`, n, TPR, and AUC (the bin's signal samples against all noise samples) per peak SNR bin, per optimal SNR and total mass quantile bin (`OPTIMAL_SNR_BINS` = 5, `TOTAL_MASS_BINS` = 4; a fixed mass is one bin), and TPR, FPR, and AUC per noise source (`EVAL-1`, `EVAL-2`, `EVAL-3`). `outside_training` flags the signal samples outside the ranges of `TRAIN_V1` (peak SNR, merger time, masses with mass2 ≤ mass1); a bin with only flagged samples is printed as `Extrapolation`, one with some as `partly extrapolation (x%)`. In `stress_v1` that is every sample with a peak SNR below 1. Until P5.8 the 12-column leaderboard took a row only for `stress_v1` (`LEADERBOARD_TESTSET`), because it had no test set column; leaderboard v2 records the set and its hash for every run (see Thresholds below), and the run prints the SHA-256. `thresholds` writes the set into `optimal_thresholds.json` (`testset`: name, seed, n, part, sha256), and `compare` titles its plot with it. `make_test_set` in `gwd.data.injection` had no caller in `src` after that and was removed in P7.4. On the laptop, `gwd_model_20251205-232013` gave ROC AUC 0.9235 on `stress_v1` (seed 0, n 1000) in two runs, the second a cache hit, and 0.9999 on `indist_v1` with the local chunks (TPR 100 % and FPR 0 % on real noise at the then fixed threshold 0.15, which fits the scale skew of real chunks below). `tests/evaluation/test_testsets.py` covers the cache, the hash, changed arrays, stale manifests and chunks, the bins, `calib_bg`, the streams, the global RNG, and the command; `tests/evaluation/test_evaluate.py` the curve, the bins, the leaderboard rule, and two runs with the same AUC.

**Thresholds and leaderboard v2 (since P5.8).** Every model has its own detection threshold (D10 = A, `EVAL-15`, `APP-3`, `hygiene:HYG-M3`). `gwd.evaluation.metrics.threshold_at_fpr(background_scores, target_fpr)` takes the lowest score of the noise-only part `calib_bg` at which at most `floor(target_fpr · n)` of its samples reach the threshold (`THRESHOLD_TARGET_FPR` = 0.01 in `gwd.config`) and returns it with the rate reached and n; if even the top score would exceed the limit (n < 100, or ties at the top, as for an untrained model that scores everything 1.0), the threshold lies just above it and detects nothing. `gwd eval thresholds` never uses the part `test` for it; `test` only reports TPR and FPR at the threshold, with n, and the six strategies of `find_optimal_thresholds` stay as a reference on `test` in the plot, the console, and `optimal_thresholds.json` (now a report with `calibrated` and `reference_strategies_on_test`). With `--save`, `gwd.registry.set_threshold` writes `threshold`, `threshold_fpr`, `threshold_fpr_achieved`, `threshold_n_background`, `threshold_strategy` (`fixed_fpr on calib_bg`), `threshold_testset` (name, seed, n, part, sha256), and `threshold_date` into the model's `.json` and keeps the other keys; a model without a `.json` gets one. `gwd.registry.get_threshold(path)` returns it, or `THRESHOLD_FALLBACK` = 0.5 with a `MissingThresholdWarning` that names the command; `threshold_record(path)` returns the keys. `gwd eval run`, `gwd eval compare`, and the Glitch Hunter call `registry.get_threshold` through the module, so one monkeypatch covers all three (`tests/evaluation/test_evaluate.py`, `test_compare.py`, `tests/apps/test_glitch_hunter.py` set it to 0.123); the constants `THRESHOLD = 0.15` and `DEFAULT_THRESHOLD = 0.46` are gone. `gwd eval run` reports TPR, accuracy, the field test, and SNR50/90 at the threshold, always with the FPR it reached on `test` and n, and says when the threshold was calibrated on another set. `snr_at_rate` now interpolates linearly between the bin centers around the crossing and skips empty bins (`EVAL-22`). `gwd eval compare` marks each model's operating point with a star and ranks by ROC AUC with TPR and FPR next to it. Leaderboard v2 (`gwd.evaluation.leaderboard`, `evaluation:MISS-5`) is `results/leaderboard_v2.csv` (`LEADERBOARD_FILE`) with 31 columns (`COLUMNS`): `schema_version` = 2, model, ISO date, the test set (name, seed, n, SHA-256, scenario, backend from its manifest, noise source of `test`), `roc_auc`, `ap`, `threshold` with its target FPR and calibration set hash (empty for the fallback), `tpr_at_fpr`, `fpr_achieved`, `n_signal`, `n_noise`, peak and optimal SNR50/90, and the field test counts as integers (empty without `--real`). ## Import rules

Since P2.6, `tests/test_architecture.py` enforces these rules. It parses every module in `src/gwd/` and `main.py` with `ast` and counts an import as lazy only inside a function body; a `try` block at module level is not lazy. The standard library is always allowed, and anything not listed under "May import" fails, so the test also limits where tensorflow, gwpy, and pycbc may appear at all. **Preprocessing (since P3.2).** `gwd.data.preprocessing` has three public functions. `condition_strain(ts, fs, notches=NOTCH_FREQS, band=BANDPASS)` resamples a gwpy `TimeSeries` to `fs`, applies one notch per frequency, then the band-pass, and returns a numpy array. It is a band-pass, not whitening. It calls the methods of the series it gets and never imports gwpy itself. The noise download, the field test (through `conditioned_crop` since P4.3), and the Glitch Hunter use it; it is bit-identical to the old download chain. The field test now also notches 240 Hz, the one behaviour change of P3.2. `normalize(x, eps=1e-10)` is the z-score `(x - mean) / (std + eps)`. The eps is absolute: on conditioned strain (std near 1e-21) it dominates the std, so the field test and the Glitch Hunter pass `eps=0` there, as they had no eps before. All other callers use the default; for the synthetic test sets, which had no eps, this changes values by a relative 1e-10. Since P4.3, `conditioned_crop(ts, fs, pad_s)` runs `condition_strain` on a padded series and cuts `pad_s` off each end (see Field test below); it raises `ValueError` for a negative pad or a series not longer than both pads.

**GWOSC access (since P3.4).** `gwd.data.gwosc` is the only place that downloads from GWOSC. `fetch_strain(detector, start, end, pad_s=0, cache=True, verbose=False)` imports gwpy inside the function, calls `TimeSeries.fetch_open_data` for `[start - pad_s, end + pad_s)`, and returns the raw `TimeSeries`. It raises `StrainError` (a `ValueError`) if the sample count does not match the requested span at the series' sample rate, or if any sample is NaN; nothing is resized or padded. `pad_s=0` gives an unpadded window; the field test pads since P4.3 (see below), and the Glitch Hunter since P4.4. `cache=True` lets gwpy keep a local copy of the downloaded file (astropy's download cache), which the old calls did not. `EVENTS` is a tuple of `Event(name, gps, kind, mass1, mass2, in_training_range)` with the nine events of the old Glitch Hunter list, in the same order and with the same GPS times. The masses are rounded source-frame medians from GWTC-1 and GWTC-2, written down from the literature and not verified offline. `in_training_range` means both masses lie in the 5–100 M☉ of `TRAIN_V1` (since P3.5; before, of `generate_random_bbh_parameters`); GW170817 (BNS) and GW190814 (2.6 M☉ secondary) are out of range. The field test (`gwd.evaluation.real_data` since P4.3) picks its five events from `EVENTS` by name (`FIELD_TEST_EVENTS`, old order); a rejected download scores the event as `None` instead of an `np.resize`d window. The Glitch Hunter draws from `EVENTS` and falls back to the simulation on a rejected download instead of trimming or zero-padding. `fetch_noise` downloads its segment through `fetch_strain` and writes nothing if the download is rejected; since P4.3 it drops the first and the last chunk (see below). Importing `gwd.data.gwosc`, `fetch_noise`, `evaluate`, `real_data`, or the Glitch Hunter does not load gwpy (`tests/data/test_gwosc.py`). The download length `NOISE_FETCH_SECONDS` stays in `gwd.config`: moving it next to `START_GPS` in `fetch_noise.py` would bring back the literal 4096 that the P3.1 check forbids in `gwd.data`, and P6.3 replaces the single segment with configurable windows anyway. Tests mock `fetch_open_data` or `fetch_strain`; one real download runs only under the `network` marker, which CI never selects.

**Field test (since P4.3).** `gwd.evaluation.real_data` holds the field test, which `evaluate` ran inline before; `gwd eval run` runs it only with `--real` (D10: optional, default off), so the evaluation runs offline. `load_window(start, end)` downloads with `fetch_strain(..., pad_s=PAD_S)` (16 s), and `gwd.data.preprocessing.conditioned_crop(ts, fs, pad_s)` conditions the padded series as a whole with `condition_strain` and then cuts `pad_s` off each end. Before, each 4 s window was conditioned on its own, so the filters rang at its ends at test time only, while the training noise is conditioned in one piece (`core:MISS-2`, `EVAL-4`). Data that are too short after the crop raise `StrainError`, and the event is skipped. The noise test loads its 200 s the same way and scores the 50 windows in one batch. Events and noise windows count at score ≥ threshold (`predict_labels`). The events inside the training mass range and the OOD events (`in_training_range=False`, here GW170817) are counted separately as `EventCount(found, loaded, total)` (`core:MISS-4`); a group with a missing event reads `n/a (k of n loaded)` instead of counting it as missed (`EVAL-13`). The leaderboard column `Real_Events_Found` holds both, for example `4/4; OOD 0/1`, and `Real_Noise_FAR` holds `k false alarms in T h` instead of a rate per year from 200 s (`EVAL-21`); without `--real` both are `n/a`. The schema kept its twelve columns until P5.8; leaderboard v2 stores the same counts as integers (see Thresholds below). Appending a row now reads the old rows as strings (`dtype=str`, `keep_default_na=False`); before, pandas turned `n/a` into an empty cell and `0.9000` into `0.9`. Downloads are cached by gwpy (`cache=True` since P3.4). `tests/evaluation/test_real_data.py` mocks `fetch_strain`. On synthetic noise with a 0.2–10 Hz part of std 3e-19 (raw H1 strain has a std of a few 1e-19, almost all below 10 Hz), the RMS of the first and last 0.1 s against the middle 0.1 s, pooled over 20 realizations, is 1.00 with the pad and 9.7 without. A 0.2 Hz sine of 3e-19 alone, as the plan suggested, gives no measurable edge transient, because `sosfiltfilt` extends the data with odd symmetry, so the test uses the broader low frequency part. On the real H1 windows of the five events the ratio was 1.1 to 16.6 without the pad (GW170104: 16.6) and 0.3 to 1.9 with it; real data with an event in the window are no clean test of the ratio, so these values are only a rough sign. `gwd data fetch-noise` conditions its 4096 s in one piece, so only its first and last chunk hold filter ringing; since P4.3 it writes chunks 1 to 1022 under their position in the segment and keeps all files already in the folder, naming those that are not from the new download on stderr (`evaluation:MISS-4`). The owner's existing chunks were not downloaded again. The field test results of older models change and cannot be compared with older leaderboard rows (see the PR of P4.3).

## Scenarios and SNR definition (current state, V1)

Training, evaluation, and the Glitch Hunter draw from different distributions. Since P3.5 these are named as `TRAIN_V1`, `EVAL_V1`, and `APP_V1` in `gwd.data.scenarios`, without changing them. P6.2 adds a corrected V2 next to them (see Scenario V2 below), and P6.6 adds V3, which is V2 with whitening (see Scenario V3 below); V1 stays the default of `gwd data generate`, the evaluation, and the Glitch Hunter without a model until P6.5.

| | `TRAIN_V1` | `EVAL_V1` | `APP_V1` |
|---|---|---|---|
| Used by | `gwd.data.generate`; Glitch Hunter, mode 'Training' (since P4.4); test set `indist_v1` (since P5.7) | test set `stress_v1` (since P5.7), the default of `gwd.evaluation.evaluate`, `thresholds`, and `compare` | Glitch Hunter, mode 'Challenge' (`gwd.apps.glitch_hunter.sources`) |

**Injection (since P3.5).** `gwd.data.injection` is the only place that draws and injects signals. `make_sample(scenario, rng=None, has_signal=None, snr=None, noise_provider=None)` returns a `Sample` with `data = noise + signal`, the noise, the scaled signal, the `InjectionParams` (masses, distance, merger time, SNR), the SNR it scaled to, and `noise_kind` (`real` or `white`). `draw_params` draws masses, then merger time, then SNR; a fixed `snr` (the sensitivity curve) is not drawn. `make_test_set` built the normalized `(X, y)` that `evaluate`, `thresholds`, and `compare` each used to build in their own loop; since P5.7 they use the fixed sets of `gwd.evaluation.testsets` instead, which call `make_sample` themselves, and P7.4 removed `make_test_set`. `rng` is anything with the numpy `RandomState` methods and defaults to the global `np.random`, as before. Since P5.3 the module passes it to `gwd.core.noise.white_noise` (`generate_gaussian_noise` until P5.4) and `gwd.core.population.random_bbh_params`; from P3.5 to P5.3 it repeated their draws itself, because `gwd.core` had no `rng` parameter. The real noise provider (`real_noise_provider`, `load_random_real_noise`) lists the chunks with `sorted(glob)` and picks one with the same `rng`, so a seed picks the same chunk on every file system; before, `random.choice` from Python's `random` module picked from an unsorted list. `Scenario.hash()` is a SHA-256 prefix of all fields that is the same in every process, unlike Python's `hash()`; `tests/data/test_injection.py` pins the three V1 hashes. Until P6.2 a scenario with `condition_signal=True` raised `NotImplementedError`; since then it is a V2 scenario (see Scenario V2 below). Since P4.1 a `Sample` also has `noise_file` (the chunk's file name) and `waveform_backend` (`pycbc`, until P6.1 also `newton`; since P5.2 the `backend` argument of `make_sample`, which defaults to `gwd.config.WAVEFORM_BACKEND`), and the real noise provider returns `(noise, file name)`. A chunk that is too short or unreadable still falls back to white noise, but now warns and is recorded as white instead of real; the random stream is unchanged.

The draw order for `TRAIN_V1` was the one of the old generator, so its files were bit-identical without real noise (golden (d), and 40 samples on the PyCBC backend), and so was the sensitivity curve; since P5.3 the time axis and the dropped spin and inclination draws change them on purpose (see Core details below). The ROC, threshold, and comparison sets now draw the merger time before the SNR, and the Glitch Hunter draws the label before the noise and with `rand() > 0.5` instead of `np.random.choice`. The distributions are the same, but the same global seed gives other samples there; no seed was set before, so no stored result depended on it. `tests/data/test_injection.py` checks bit-identical batches for the same seed, also with the chunk list in reverse order, the bounds of every drawn parameter, and the V1 scale of real chunks. `test_known_skew` (`xfail(strict=True)`) asks for `TRAIN_V1` and `EVAL_V1` to draw from the same distribution and fails until V2.

**SNR definition (since P5.5).** V1 scales every signal to a peak SNR: the signal's peak divided by the noise standard deviation. That is an amplitude ratio, not a matched filter SNR, so detectability at the same value depends strongly on the masses and the noise type (`data-training:SNR-DEF`, `evaluation:MISS-2`). `gwd.core.snr` names both definitions: `peak_snr(h, sigma)` = max|h|/σ, `optimal_snr_white(h, sigma)` = √Σh²/σ, `optimal_snr_psd(h, psd, fs, f_low, f_high)` = √(4 Σ |H(f_k)|²/S(f_k) df) with H = rfft(h)/fs over the bins f_low ≤ f < f_high (the convention of `pycbc.filter.sigma`; without a band from the first bin above DC to Nyquist, which counts half, so a flat PSD 2σ²/fs gives `optimal_snr_white`), and `optimal_snr_welch(h, noise, fs, f_low, f_high)`, the same against the Welch PSD of a noise series (Hann, 0.25 s segments, interpolated onto the grid of h; 1 s segments biased ρ about 7 % high). `measure(h, kind, ...)` and `scale_to_snr(h, target, kind, ...)` take the definition by name (`peak`, `optimal_white`, `optimal_psd`, `optimal_welch`). `scale_signal_to_snr`, the V1 peak scaling with `noise_std` or `unit`, moved there from `gwd.data.injection` with the same arithmetic, so golden (c) did not change. `gwd.core.snr` imports numpy and scipy only. The peak SNR still drives V1. `make_sample` also measures the optimal SNR of every signal sample (`Sample.optimal_snr`; `Sample.peak_snr` is `Sample.snr`) with `measure_optimal_snr`, which draws nothing from `rng`: in white noise analytically with the known σ = 1 (`WHITE_NOISE_SIGMA`), in a real chunk against the Welch PSD of that chunk in `BANDPASS` (20–300 Hz), because the chunk is band-passed but the V1 signal is not, so above the band the PSD is near zero and ρ would explode. `labels.csv` gets `peak_snr` and `optimal_snr` after `noise_file` (0 without signal); `snr` stays as an alias with the value of `peak_snr`, so readers from before P5.5 keep working. Readers of old datasets, which have only `snr`, read it as the peak SNR: the validator's range check and statistics read `snr`, which both have, and report the optimal SNR as not recorded. `check_snr_columns` checks the new columns when they are there (both present, numeric, `peak_snr` = `snr`, `optimal_snr` > 0 for signals, both 0 for noise). Golden (d) gained the two columns in the commit `golden: record peak_snr and optimal_snr in labels.csv`. `gwd data validate` prints the median `optimal_snr / peak_snr` per noise source and plots optimal against peak SNR; `gwd eval run` records the mean optimal SNR of each peak SNR level of the sensitivity curve and reports SNR50 and SNR90 as both (the leaderboard keeps the peak values). `tests/core/test_snr.py` checks `measure(scale_to_snr(h, x)) == x` for every definition, ρ_opt/peak = 13.47 for a 30/30 M☉ chirp in white noise (the finding said 13.5), `optimal_snr_psd` against `pycbc.filter.sigma` with the aLIGO PSD (±1 %), and the Welch variant on colored noise from `pink_psd` and from the aLIGO PSD (±10 %). Measured on the laptop's 1024 chunks with `TRAIN_V1` (500 signal samples, seed 0, random masses): ρ_opt/peak is 11–21 (median 16) in white noise and 25–89 (median 52) in real noise, and ρ_opt runs from 19 to 916 (median 254); for 30/30 M☉ (50 samples) the median ratio in real noise is 42 against 13.5 in white noise. The same peak SNR is thus about three times louder in real noise, which is the data for D2.

**Provenance (since P4.1).** Two things decide what the data contains: the waveform backend, and whether `data/noise_background/` has chunks. Until P5.2 the backend was a switch in the environment too (whether PyCBC could be imported); see Waveform backend below. `gwd.data.provenance` prints the line `Backend: ... | Noise: ...` at the start of `gwd data generate` and `gwd eval run`; in `generate` for a scenario with real noise but no chunks, a warning block follows on stderr (until P6.1 also for a backend of `newton`, which only tests and the golden values chose). `labels.csv` has three columns after the old seven: `waveform_backend` (`pycbc`, until P6.1 also `newton`; empty without signal), `noise_source` (`real` or `gaussian`; `noise_kind` `white` is written as `gaussian`), and `noise_file` (the chunk's file name, empty for Gaussian noise). Empty cells read as NaN in pandas unless `keep_default_na=False`. `<out>/manifest.json` holds `format`, `scenario` and `scenario_hash`, `seed`, `n`, `time_axis` (since P5.3 `arange(n)/fs`; a manifest without it was written on `linspace`), `waveform_backend` (`backend_label(backend)`, for example `pycbc 2.10.0`), `signal_backends` (signal samples per backend), `real_noise_fraction` and `real_noise_samples` (what was drawn), `scenario_real_noise_fraction`, `noise_chunks`, `noise_dir`, the versions of gwd, numpy, pycbc, and pandas, `git_commit` and `git_dirty` (null outside a Git checkout), and `labels_sha256`. It has no timestamp, so the same data from the same commit, noise folder, and working tree state gives the same manifest and hash (`tests/data/test_generate.py`). Training copies its SHA-256 into the model's `.json` (see Training above). The golden dataset values gained the three columns in a `golden:` commit; nothing else changed. `tests/data/test_generate.py` checks the columns, the manifest, the start line, and both warnings; the end-to-end test (until P7.4 the smoke test) checks them in the pipeline and in the model's `.json`.

**Waveform backend (since P5.2).** `gwd.core.waveforms.generate_chirp(time, t_merger, backend=..., mass1=..., ...)` replaces `chirp_and_backend` and `generate_astrophysical_chirp`; it returns `(strain, frequency)`. `backend` is a required keyword, `pycbc` (until P6.1 also `newton`), because `gwd.core` reads no config; an unknown name raises `ValueError`. The pipeline passes `gwd.config.WAVEFORM_BACKEND`, which is `pycbc`: `gwd.data.injection` (`make_sample`), `generate_dataset`, and `gwd.data.provenance`. PyCBC is imported only when a chirp is drawn (`python -X importtime -c 'import gwd.core.waveforms'` names no pycbc). A missing PyCBC raises `WaveformBackendError` with the install command (since P6.1 `pip install -e .`; before, the `physics` extra) and the pointer to WSL, and an error of `get_td_waveform`, for example an unknown approximant, raises `WaveformBackendError` with the parameters and the PyCBC error as its cause. Before, both drew a Newton chirp with a print (and since P4.1 a warning) (`CORE-4`, `CORE-17`, `hygiene:HYG-M1`, `core:MISS-1`). `HAS_PYCBC`, `active_backend()`, and `WaveformFallbackWarning` are gone; `check_backend(backend)`, `pycbc_available()`, and `backend_label(backend)` take their place. `generate_dataset` checks the backend before it clears or writes the output folder, `gwd eval run` and `gwd eval thresholds` before they load the model, `gwd eval compare` draws its test set before it loads any model, and `gwd app glitch-hunter` checked it in the CLI handler until P4.4; since then the Glitch Hunter starts without PyCBC with its simulation off (see Glitch Hunter below). `gwd.cli.main` prints a `WaveformBackendError` on stderr and returns 1, without a traceback. `make_sample` and `generate_dataset` take a `backend` argument; `gwd data generate` never passes it, and until P6.1 only the tests and `tests/golden/regen.py` passed `newton`, so the golden dataset and Newton values stayed numpy-only. `TimeDomainSimulator` takes `backend` as a required keyword too. Until P6.1 the waveform explorer (`choose_backend()`) used `newton` without PyCBC, in red at the top of its window (default of D1); P6.1 removed that branch (see Newton backend deleted below). `generate_realistic_chirp` took `backend` too until P5.3 deleted it. `tests/core/test_waveforms.py`, `tests/data/test_generate.py`, `tests/evaluation/test_evaluate.py`, `tests/test_cli.py`, and `tests/apps/test_demo_apps.py` block PyCBC with `sys.modules['pycbc'] = None`.

**Newton backend deleted (since P6.1, D1 = A).** `gwd.core.waveforms` has one backend, `pycbc` (`BACKENDS = ("pycbc",)`); `_newton_chirp` and its known errors (`CORE-2`: frequency π^(5/8) ≈ 2.045 too high, `CORE-3`: amplitude 4 times too large, `CORE-8`: no `f_lower`, no ISCO cut, ignored parameters) are gone, and the Git history keeps them (`git log -p -S _newton_chirp -- src/gwd/core/waveforms.py`). `backend="newton"` raises `ValueError` like any unknown name. The install hints say `pip install -e .` and point to WSL on Windows. The tests that passed `backend="newton"` for speed or to avoid PyCBC (`tests/core/test_rng.py`, `tests/core/test_snr.py`, the test sets in `tests/evaluation/`, `tests/data/test_scenario_v2.py`) draw with PyCBC now; tests check that `newton` is refused. The dataset is compared with `rtol=1e-6` instead of `1e-9`, room for rounding differences of PyCBC between machines. Variant B (a corrected `core/newtonian.py`) was not done.

**Core details (since P5.3).** `gwd.core.timebase.time_axis(fs, duration, t0=0.0)` returns `t0 + np.arange(n) / fs` with `n = round(fs * duration)`; it replaces `np.linspace(0, duration, n)` in the injection, the time domain simulator, the Glitch Hunter, the validation plots, and the golden values. The spacing of `linspace` was `duration / (n - 1)`, an effective 4095.75 Hz instead of 4096 Hz (`CORE-19`, `DATA-19`), so PyCBC now draws with `delta_t` exactly 1/4096 s and new datasets differ from old ones by about 0.006 % in the sampling; `manifest.json` records `time_axis`. `generate_chirp` raises `ValueError` for a `t_merger` outside `[t[0], t[-1]]` instead of moving the merger to the edge, and its default is `t[0] + 0.9 (t[-1] - t[0])` instead of `0.9 t[-1]`, which assumed `t[0] = 0` (`CORE-15`). Its frequency is NaN where the chirp has no signal, on both backends, instead of 0. Where the window cuts a PyCBC waveform, at the start or the end, the cut edge is faded with the cosine half of a Tukey window of `TAPER_SECONDS` = 50 ms; before, the start had a 50-sample ramp whatever its comment said (`CORE-14`). The PyCBC frequency comes from the phase of h+ − i h×, so it is not meaningful edge-on (inclination π/2); the pipeline draws face-on chirps. `gwd.core.constants` holds `C`, `G`, `M_SUN`, `MPC` (the values of LAL) and `LASER_WAVELENGTH`, which the Newtonian chirp, the interferometer model, and the simulator used to repeat with rounded values (P6.1 removed `G`, `M_SUN`, and `MPC` with the Newton code, their only user); the unused `self.c` of the simulator and the `* 1.0` of the shot noise are gone (`CORE-18`). `generate_realistic_chirp`, which cut off the merger and was never called, is deleted (`CORE-1`). `gwd.core` draws only from an `rng` it is given, a numpy `Generator` or `RandomState` (`core:MISS-3`, `DATA-5`): `generate_gaussian_noise` and `generate_colored_noise` (since P5.4 `white_noise` and `colored_noise_from_psd`) take a required keyword `rng`, so does `TimeDomainSimulator`, and the waveform explorer passes `np.random.default_rng()` or the `rng` of `build_figure(rng=...)`. `gwd.core.population.random_bbh_params(rng, masses, max_distance_mpc)` replaces `generate_random_bbh_parameters`: mass1 log-uniform, mass2 log-uniform up to mass1, distance uniform in volume up to 2000 Mpc and metadata only, no claim of 'O3' distributions; spins and the inclination are not drawn, because V1 chirps are spinless and face-on (`CORE-16`, `DATA-18`). This is an announced behaviour change: a random-mass sample draws three numbers fewer, so the same seed gives other `TRAIN_V1` merger times, SNRs, and later samples than before, from the same distributions; white noise and fixed-mass scenarios draw the same numbers. The golden Newton, PyCBC, and dataset values changed in the commit `golden: time_axis/arange, constants, and random masses without spin draws`; noise, scaling, and interferometer did not. `tests/core/test_rng.py` checks bit-identical draws for the same seed with a `Generator` and a `RandomState`, that the global numpy RNG stays untouched, and that no `np.random.<draw>(` call is left in `src/gwd/core`; `tests/core/test_timebase.py` and `tests/core/test_population.py` cover the axis and the parameter laws.

**Noise and interferometer (since P5.4).** `gwd.core.noise` has `white_noise(n, sigma, rng=...)`, which draws as `generate_gaussian_noise` did, and `colored_noise_from_psd(n, fs, psd, rng=...)`. `psd` is a one-sided PSD in units²/Hz, a function of the frequency or an array on `np.fft.rfftfreq(n, 1/fs)`. Each positive frequency bin gets a complex Gaussian coefficient with E|X_k|² = n·fs·S(f_k)/2, the Nyquist bin a real one, and DC zero, so the Welch PSD of the noise matches `psd` and its variance is the integral of `psd` up to fs/2, for any n and fs. Before, `generate_colored_noise(length, sample_rate, noise_level)` multiplied white noise of std `noise_level` by √(10/f) in the FFT, so its std was not `noise_level` and depended on the length and the sampling rate (`CORE-9`). Its 1/f spectrum, called 'seismic' before, is now `pink_psd(f, psd_at_f_ref=1.0, f_ref=10.0)`, a shape and not a detector model. `tests/core/test_noise.py` checks the Welch PSD of a pink and a flat PSD in four bands within 15 % for (n, fs) = (16384, 4096), (16384, 1024), and (2048, 4096), the variance against the integral, and that the flat PSD 2σ²/fs gives the std σ for each pair; the strict xfail for `CORE-9` became that last test. `InterferometerModel` is a qualitative learning model (D6 = A): its docstring lists the formulas and the ad hoc factors, which are module constants of `gwd.core.interferometer` (`MIRROR_MASS`, `TEMPERATURE`, `SQUEEZING_FACTOR`, `THERMAL_SCALE`, `COATING_WEIGHT`, `SEISMIC_LEVEL`, `RADIATION_PRESSURE_SCALE`, `BS_LOSS_WEIGHT`, `MIRROR_LOSS_WEIGHT`, `POWER_RECYCLING_FACTOR`, and the depth, center, and width of the signal recycling dip) instead of bare numbers (`CORE-10`). The Planck and the Boltzmann constant and the arm length come from `gwd.core.constants` (`H`, `K_B`, `LIGO_ARM_LENGTH`) with their exact SI values, instead of 6.626e-34 and 1.381e-23 in the model (`CORE-18`). `reference_psd(f, low_freq_cutoff=0.0)` and `reference_asd(f, ...)` give PyCBC's aLIGO design curve `aLIGOZeroDetHighPower` at any frequency: they import pycbc and LALSimulation lazily and evaluate the LALSimulation function that `pycbc.psd.aLIGOZeroDetHighPower` evaluates on its grid (the values are equal there, except PyCBC's last bin, which it leaves at 0); like PyCBC they are 0 below the cutoff, and 0 at f ≤ 0. Without PyCBC they raise `ReferencePSDError`, and `reference_available()` is False. `tests/test_architecture.py` allows `lalsimulation` lazily in `gwd/core/interferometer.py` only. `reference_asd(100)` is 3.90e-24/√Hz; the default model is above the reference at every frequency of its curve, 270 times at 100 Hz, which `tests/core/test_interferometer.py` pins as 2 to 3 orders of magnitude, next to the directions of power, arm length, and features. The interferometer designer draws `reference_asd` as its dashed reference, labelled 'aLIGO design (aLIGOZeroDetHighPower)', instead of the invented 'LIGO Design' curve 1e-23·(f/100)^-0.5, five times higher below 40 Hz (`CORE-11`, `APP-13`); its title says 'qualitative learning model', and its info box shows the model's ASD over the reference at 100 Hz. Without PyCBC it has no reference and says so in the plot. `TimeDomainSimulator` takes a required keyword `noise_psd` and draws its noise with `colored_noise_from_psd`; `add_detector_noise(signal, noise_scale=1.0)` multiplies the noise amplitude by `noise_scale`. Before, the slider value times 1e-22 went into `generate_colored_noise` (`CORE-12`). `arm_length_change(strain)` replaces `calculate_response`, whose intensity nothing used. The waveform explorer passes `reference_psd` with a 10 Hz cutoff (below it the design PSD rises so steeply that the noise std in 0.5 s would be about 6e-21 instead of 3e-22 and hide the chirp), and until P6.1, without PyCBC, a 1/f stand-in at the aLIGO level at 100 Hz (`STAND_IN_PSD`; since P6.1 the explorer stops without PyCBC instead); the noise plot's title names the PSD, and the noise slider is labelled 'Noise (x ASD)'. The golden noise (b, `colored` only) and interferometer (e) values changed in the commit `golden: noise normalization`; `gaussian` and the dataset did not, because the white noise draws are the same.

**Validation (since P4.6).** `gwd.data.validate.check_integrity(folder, on_sample=None)` returns a list of `Finding(check, message, file)`; an empty list means the dataset is intact. It checks `labels.csv` (the seven old columns, numeric values, `has_signal` in 0/1, no duplicate file names, and since P5.5 the SNR columns, see SNR definition above), every file it lists (exists, loads with `allow_pickle=False`, shape `(N_SAMPLES,)`, float32 or float64, only finite values, not all zeros), `sample_*.npy` files it does not list (orphans), and, if there is one, `manifest.json` against `labels.csv` (`n`, `labels_sha256`) and its scenario (known name, same `Scenario.hash()`). Before, 10 random files were loaded (`DATA-22`). `check_distribution(labels, scenario)` checks the signal samples against `signal_ranges(scenario)`, which takes the SNR, mass, and merger time bounds from the scenario's own fields (fixed masses must equal them; random masses must also have `mass2 <= mass1`), with a relative slack of 1e-9 for floats stored as text, and checks that the signal share is 50% ± 5%. Noise-only samples carry zeros and are not range-checked. This replaces the median SNR thresholds 5 and 8 and the classes up to `>20` from the old U(5,25) draw, which failed `TRAIN_V1` (peak SNR 1–12) at random (`DATA-4`, `data-training:SNR-DEF`); the same findings give the report and the exit code. A dataset without a manifest is `unknown (v1)` (`UNKNOWN_V1` of `gwd.data.provenance`, the same label the model metadata uses) and is only checked for integrity. `run()` prints the scenario, the counts per class, noise source, and backend, the min, median, and max of each signal parameter next to the scenario's range, and every finding (at most 20 per check on screen, with the rest counted), and returns 1 if there is any. The report plots are written only with `--plots`; the "SNR vs distance" panel is gone, because the distance does not change a sample with a normalized chirp (`DATA-18`), and the example samples are those with the lowest, median, and highest SNR. `gwd.training.train.load_data` calls `check_integrity` with an `on_sample` callback that z-scores each sample into one preallocated array, so the files are read once; any finding raises `InvalidDatasetError` (a `ValueError` that names the files), and `gwd train` prints it on stderr and exits with 1. Before, it skipped unreadable files and cut or zero-padded wrong lengths without failing (`data-training:LOAD-SILENT`). The samples were float64 until P5.6; since then `generate_dataset` stores them as `SAMPLE_DTYPE` = float32 of `gwd.config`, 65 536 bytes of data per file, drawn in float64 as before, so `labels.csv` is unchanged and only golden (d) `first_samples` changed (commit `golden: float32`; `DATA-21`). `generate_dataset(..., overwrite=False)` calls `prepare_output_folder` first: a missing or empty folder is used, any other raises `OutputFolderError` (exit code 1); with `overwrite=True` (`--overwrite`) only the folder's own `sample_*.npy` files and `labels.csv` are removed, not other files, not subfolders, and the new `manifest.json` replaces the old one when the dataset is written. The noise folder itself is refused as output. `tests/data/test_validate.py` covers each finding, the ranges, and the exit codes (also five seeds of 64 samples with rc 0); `tests/data/test_generate.py` and `tests/training/test_train.py` cover the folder rule and the loading.

**Scenario V2 (since P6.2).** `gwd.data.scenarios` has four V2 scenarios, all with `version` 2, `condition_signal=True`, `snr_kind="optimal"`, `peak_reference=None`, `simulated_noise="aligo"`, `pad_s` = 2.0, and no real noise (D3 = B; real noise for V2 is P6.3):

|---|---|---|---|---|
| Used by | `gwd data generate --scenario train_v2` | test set `indist_v2` | test set `stress_v2` | Glitch Hunter, V2 'Challenge' |
| Optimal SNR (20–300 Hz) | 4–20 | 4–20 | 2–20 (2–4 is the extrapolation bin) | 4–8 |

`INDIST_V2` is `TRAIN_V2` under another name, so the test set can differ from the training data only by seed and n (`test_v2_consistent`). The two new fields `simulated_noise` ('white' or 'aligo') and `pad_s` are left out of `Scenario.hash()` at their V1 values ('white', 0.0), so the three V1 hashes, and with them the existing manifests and test sets, are unchanged (`stress_v1`, seed 0, n 1000, still has the SHA-256 `00a4d6967b55…` of P5.8). `__post_init__` accepts a V1 scenario only with a peak SNR, a peak reference, white simulated noise, and no pad, and a V2 scenario only with an optimal SNR, no peak reference, a positive pad, and no real noise. The ranges are a choice of this step: the optimal SNR 4–20 lies around the usual detection threshold of 8 (`TRAIN_V1` gave 19 to 916, see SNR definition above); P6.5 trains on it.

`make_sample` passes a V2 scenario to `make_conditioned_sample(scenario, rng, has_signal, snr, backend)`, which draws (1) the label, (2) raw noise of `N_SAMPLES` + 2 · 8192 samples, Gaussian with the aLIGO design PSD (`colored_noise_from_psd` with `reference_psd`, 0 below `SIMULATED_PSD_F_LOW` = 10 Hz, where the design PSD rises by seven orders of magnitude; the band-pass removes that part anyway) or white with std 1, and (3) the parameters (`draw_params`, as in V1). The chirp is drawn on the padded time axis (`time_axis(fs, 8.0, t0=-2.0)`), so the window cuts no waveform with a taper, and scaled by `scale_factor_v2` so that its part inside the window has the drawn optimal SNR against the same PSD in `BANDPASS` (`optimal_snr_psd`, D2 = B). Noise plus chirp then pass `gwd.data.preprocessing.condition_array(x, fs, pad_s)`, which wraps the array in a gwpy `TimeSeries` and calls `conditioned_crop`, the chain of the field test and the Glitch Hunter (notches at 60–240 Hz, band-pass 20–300 Hz, pads cut off); the chirp alone passes it too, to return the signal part. Data, noise, and signal are divided by the std of the conditioned sum, normalized with eps 0, so every sample has mean 0 and std 1 whatever its noise. `Sample.optimal_snr` is the drawn optimal SNR, `Sample.snr` the peak SNR of the conditioned signal over the std of the conditioned noise, measured, and `noise_kind` is `aligo` (`noise_source` `aligo` in `labels.csv`) or `white`. V2 needs gwpy (extra `gwdata`) and PyCBC; without gwpy `condition_array` raises `ImportError` with the install command. On the laptop a V2 sample takes about 0.1 s, 64 samples about 3 s.

The validator checks the SNR range of a V2 dataset against `optimal_snr` (`snr_column`), and its SNR histogram shows that column. The test sets `indist_v2` and `stress_v2` (`INDIST_V2_SET`, `STRESS_V2_SET`, bin width 2, training reference `TRAIN_V2`) are drawn and binned in the optimal SNR: `EvalSet.peak_snr_bin_width` and `peak_snr_edges()` became `snr_bin_width` and `snr_edges()` in the scenario's `snr_kind`; `testsets.bins` gives equal bins in the drawn SNR and quantile bins in the other; `outside_training` checks the SNR of the training scenario's kind, so in `stress_v2` exactly the bin 2–4 is `Extrapolation`; and `evaluate.efficiency_curve` returns the centers of the drawn SNR with the mean of the other, so for a V2 set the optimal SNR50/90 come from the centers and the peak values from the means, and the plot's x axis is the optimal SNR. Their manifests store the masses, merger time, and both SNRs of every sample, for P6.4. V1 sets draw and bin as before.

`tests/data/test_scenario_v2.py` holds the checks of the plan, measured on the laptop: (a) the same seed gives a bit-identical sample; (b) for 5 mass pairs from 5/5 to 100/100 M☉ and 3 seeds each, the optimal SNR measured in the conditioned sample (Welch PSD of its noise, 20–300 Hz) over the target 8 is 0.96–1.02 in aLIGO noise and 0.97–1.07 in white noise, inside [0.9, 1.1]; (c) at most 0.11 % of the conditioned signal's energy lies above 300 Hz, against 5.4 % for an unconditioned V1 chirp of 5/5 M☉; (d) `test_v2_consistent`. It also checks the normalization for both noise types, the PSD of the simulated noise, the filter ringing (in a prototype the edge to middle RMS ratio of 20 aLIGO noise samples was 1.04 with the 2 s pads and 1.23 without; the test asks for 0.9–1.15), that V1 draws as before, the V2 test sets, their extrapolation bin and manifest, the efficiency curve, and a V2 dataset that validates. A CPU smoke run in a tmp `GWD_HOME` (`gwd data generate --scenario train_v2 --n 64 --seed 1`, `gwd data validate`, `gwd train --epochs 1`, `gwd eval thresholds --testset indist_v2 --n 32 --save`, `gwd eval run --testset stress_v2 --n 32`) ran with exit code 0 (AUC 0.51 after one epoch on 64 samples: the path works, the model has learned nothing). V2 conditions but does not whiten, as the real-data chain did not until P6.6; the peak SNR at optimal SNR 8 is only about 1 to 2 in the conditioned aLIGO noise, which P6.5 will show is hard or not. P6.6 adds the whitening as scenario V3 (below).

**Scenario V3 (since P6.6).** The owner trained a first V2 model, `gwd_model_20261116-204058`, on 10 000 `TRAIN_V2` samples (seed 42, best epoch 9 of 14). On `indist_v2` (seed 0, n 1000) it reached ROC AUC 0.865 and TPR 39.8 % at FPR ≤ 1 %, and needed an optimal SNR of about 14 for 50 % and about 19 for 90 % detection; by optimal SNR bin it detected 2–3 % at 4–8 and 18–22 % at 8–12. A matched filter with the right template does far better: in Gaussian noise its statistic has mean ρ_opt and standard deviation 1, so at ρ_opt 8 it lies far above any threshold at FPR 1 % (a single template, without a search over a template bank). One suspected cause: V2 band-passes, notches, and z-normalizes, but does not whiten, so the strongly coloured aLIGO noise, whose PSD spans a factor of 33 between 20 and 300 Hz and is largest at the low end, dominates the input where it is loudest, and the CNN has to learn the inverse filter itself. V3 tests that cause: it whitens before the band-pass, as a matched filter search does, and changes nothing else.

| | `TRAIN_V3` | `INDIST_V3` | `STRESS_V3` | `APP_V3` |
|---|---|---|---|---|
| Used by | `gwd data generate --scenario train_v3` | test set `indist_v3` | test set `stress_v3` | Glitch Hunter, V3 'Challenge' |
| Same as | `TRAIN_V2` | `INDIST_V2` | `STRESS_V2` | `APP_V2` |

Each V3 scenario is its V2 counterpart with `version` 3 and the new field `whiten=True` (`tests/data/test_scenario_v3.py` checks that nothing else differs). `whiten` is left out of `Scenario.hash()` at False, like the V2 fields in V1, so the V1 and V2 scenario hashes and test set hashes are unchanged: a slow test rebuilds `stress_v1` (seed 0, n 1000, SHA-256 `00a4d6967b55…`) and `indist_v2` (seed 0, n 1000, `c159ad58094e…`, the set of the owner's run above) and two small sets and compares their hashes. `make_conditioned_sample` draws exactly as in V2 (label, raw noise, parameters, chirp scaled to the optimal SNR); only the conditioning differs: the padded sum is whitened with the PSD the noise was drawn from (`simulated_psd('aligo', n)`, 0 below 10 Hz), then notched, band-passed, cropped, and normalized as in V2, and the chirp alone passes the same chain. `gwd.data.preprocessing.whiten(x, fs, psd, taper_s=0)` is the one whitening of the package: it divides every frequency bin by √(S·fs/2), so noise with PSD S comes out white with unit variance, and sets DC and bins without power to 0; numpy and scipy only. Whitening is linear and invertible in the band, so the optimal SNR keeps its meaning: against the aLIGO PSD it equals that of the whitened chirp against the flat PSD of unit white noise (a test checks this to 1e-9 for 5 mass pairs), and measured in the whitened, conditioned sample against the Welch PSD of its noise it is within 10 % of the drawn value (as test (b) of V2).

Simulated samples are whitened with the known PSD, real data with an estimate. The known PSD is exact for the simulated noise, which is periodic in its padded segment (it is drawn in the frequency domain), so no taper is needed, the injected chirp cannot bias the estimate, and a V2 and a V3 sample differ only by the whitening. An estimate from the 8 s padded segment would add its own error: whitened with Welch PSDs of that segment, 10 noise samples correlated with the known PSD version at 0.926 on average (4 s segments) and 0.987 (1 s segments), measured on the laptop. Real data have no known PSD. `whiten_strain` resamples a padded gwpy series to 4096 Hz and whitens it with `welch_psd_on_grid` of the whole padded segment (Hann, `WHITEN_PSD_SEGMENT_S` = 4 s, half overlap, median average) after a Tukey taper of `WHITEN_TAPER_S` = 1 s at each end; `conditioned_crop(..., preprocessing="whiten_bandpass")` calls it before the notches and the band-pass. For the 36 s of an event window, this agrees with the known PSD path: on simulated aLIGO noise plus a component below 10 Hz with a std of 3e-19, as raw H1 strain has, the conditioned windows correlate at 0.987–0.990 with those whitened with the known PSD (10 seeds), and the edge to middle RMS ratio is 0.99 (the test asks for > 0.97 and 0.85–1.15). The median makes a short loud event inside the segment barely change the estimate.

After the whole chain the noise of a V3 sample has the spectrum of white noise through the same notches and band-pass, within 0.90–1.22 per 10 Hz band (V2: 0.81–15.5), so what is left is the ripple of gwpy's band-pass, which V2 and the real data path have too. Every sample has mean 0 and std 1, the pads keep the filter ringing out (edge to middle RMS 0.999), and whitening costs little: `gwd data generate --n 4000` took 60 s for `train_v2` and 62 s for `train_v3` on the laptop, the two running at the same time.

The test sets `indist_v3` and `stress_v3` draw from the random streams of `indist_v2` and `stress_v2` (`EvalSet.stream`, `part_rng(spec.stream_name, ...)`): with the same seed and n they hold the same labels, parameters, and raw noise realizations, only preprocessed differently. A test records the raw noise each set draws and compares it array by array. So a V2 and a V3 model can be compared per optimal SNR bin on the same physical events. Their manifests name the stream and the preprocessing; their training reference is `TRAIN_V3`. `indist_v3` (seed 0, n 1000) has the SHA-256 `bdf05eb199fb…` on the laptop.

A tiny CPU check, only an indication and not a result: `train_v2` and `train_v3` with 4000 samples each (seed 1, so the same events), `gwd train --epochs 5 --seed 7` on each, thresholds and evaluation on `indist_v2` (seed 0, n 400; the V3 model was scored on `indist_v3` through the counterpart rule) gave ROC AUC 0.834 for the V2 model (TPR 26 % at FPR 1.0 %) and 0.889 for the V3 model (TPR 36 % at FPR 0.5 %). Both models had a validation accuracy of 0.5 at score 0.5 in every epoch; the AUC difference on 200 signal samples from one seed says little. A full training on the GPU (as for `gwd_model_20261116-204058`) decides whether whitening helps.

**Preprocessing follows the model (since P6.6).** `gwd.data.scenarios` names the two preprocessings, `PREPROCESSINGS = ("bandpass", "whiten_bandpass")`, and every scenario has one (`Scenario.preprocessing`). `gwd train` writes it into the model's `.json` as `preprocessing`, next to `dataset_scenario` (`bandpass` for a dataset without a manifest or with an unknown scenario). `preprocessing_of(metadata)` reads it back: the key, else the preprocessing of the `dataset_scenario`, else `bandpass`, so models from before P6.6 keep what they got. `gwd.evaluation.testsets.set_for_model(name, model_path)` reads the metadata through `gwd.registry.read_metadata` and returns the set to use: the named one, or its counterpart with the same draws and the model's preprocessing (`counterpart_set`; `indist_v2` and `indist_v3`, `stress_v2` and `stress_v3`), or the named one with a warning if it has no counterpart (the V1 sets). `gwd eval run` and `gwd eval thresholds` use it and print the preprocessing; `gwd eval compare` builds the named set and the counterpart a model needs, checks that their labels are equal, and passes each model its own inputs (`score_models(..., inputs)`). The field test (`run_field_test(..., preprocessing=...)`) whitens its real data for a whitening model. The Glitch Hunter's switch 'Scenario' has V1, V2, and V3 (`MODES_V3`: `TRAIN_V3` and `APP_V3`), starts in the version of the model's `dataset_scenario` (`start_version`; V1 without a model), gives its real data the model's preprocessing (without a model, that of the switch), says in the title when a simulated sample has another preprocessing than the model, and names whitened data in the spectrogram title. The CNN is unchanged.

**Known skews:**

The skews below describe V1, the default until P6.5; `test_known_skew` stays a strict xfail as their documentation. V2 removes those it names.

- The evaluation SNR range lies mostly below or at the edge of the training range (`DATA-1`, `EVAL-1`). Since P5.7 this holds for the default test set `stress_v1` only, on purpose; `indist_v1` draws from the training distribution, and the metrics per bin mark the bins below the training minimum as `Extrapolation`. In V2 `stress_v2` covers the training range in bins plus one explicit extrapolation bin.
- Training uses up to 80% real, bandpass-filtered noise, while simulation evaluation uses 100% white noise (`EVAL-2`, `data-training:NOISE-SKEW`). Since P5.7 `indist_v1` has the training's noise mix where chunks exist, and the metrics are reported per noise source. V2 trains and evaluates on the same simulated aLIGO noise.
- Evaluation uses only 30/30 M☉, while training uses random masses (`EVAL-3`); since P5.7 in `stress_v1` only, and `gwd eval run` reports the metrics per total mass bin. Since P5.5 both record the optimal SNR next to the peak SNR, so the difference is measured: peak SNR 1 is ρ_opt ≈ 13.5 for 30/30 M☉ in white noise, and the training's peak SNR 1–12 gave ρ_opt from 19 to 916 on the laptop, depending on masses and noise (see SNR definition above).
- The Glitch Hunter's simulation produced data outside the training distribution (`APP-2`). Since P4.4 its start mode 'Training' draws from `TRAIN_V1`; only 'Challenge' draws from `APP_V1`, on purpose and marked as hard. In V2 both modes lie inside `TRAIN_V2`.
- The peak SNR refers to the measured noise std in training, but to a nominal std of 1 in evaluation and the Glitch Hunter. For white noise of 16384 samples the measured std is within about half a percent of 1; for real chunks the scale skew below applies.
- Real noise is filtered, but the signal is added unfiltered (`DATA-12`, `apps:APPX-1`, `CORE-7`). V2 injects first and then conditions both together.
- Real noise chunks reach the CNN at a much smaller scale than white noise. `generate` normalizes the raw chunks (std near 1e-21) with the default eps, which dominates, so their std is about 1e-11 instead of 1. `train` normalizes again with the same eps. For the 1024 local chunks, the noise-only inputs end up with a std of 0.07–0.21, against 1.0 for white noise. Measured in P3.2 and kept as V1. V2 normalizes the conditioned sum with eps 0, so every sample has std 1.
- The noise source is a switch in the environment (`hygiene:HYG-M1`): missing chunks still mean white noise. Since P4.1 it is printed and recorded (see Provenance above). The waveform backend no longer is a switch since P5.2: without PyCBC the pipeline stops.

## Deliberately left out

The cleanup plan left these out on purpose. They are possible follow-up projects, not open steps:

- A new CNN architecture and a hyperparameter search: most of the parameters sit in one dense layer (`DATA-26`), but changing that is ML research, not cleanup. `tests/training/test_model.py` pins the parameter count (P3.7), so a change is a deliberate one.
- A Matched Filter baseline (P6.4 is dropped, D5 = B); [evaluation.md](evaluation.md#matched-filter-baseline-d5) says where the old script is and why it is wrong.
- Native Windows support for PyCBC and lalsuite: they have no Windows wheels, so the way is WSL (D1). Since P6.1 there is no PyCBC-free waveform backend either; on native Windows only the Glitch Hunter's real data and the interferometer designer without its reference curve work.
- Research-level statistics: confidence intervals, KS tests, and fits for SNR50 and SNR90. Range checks, n next to every rate, stored test set parameters, and two or three seeds when retraining (P6.5) are enough.
- A reliable false alarm rate with time slides and several detectors, segments chosen by data quality flags, and a full O3 timeline for 'LIGO random' (`EVAL-21`, `DATA-25`, `APP-19`).
- Network SNR, antenna patterns (`CORE-14`), spins, inclination, precession, and higher modes in the datasets: a later scenario version. V1 and V2 draw spinless, face-on chirps.
- A calibrated interferometer noise model (D6, option B).
- Experiment tracking, Docker, pre-commit, mypy, coverage thresholds, and HDF5 or `tf.data` pipelines.
- A history rewrite for the tool state that P1.1 removed from the index.
