# GWD Architecture

This document describes the target structure of the project, where the code is today, and how far the cleanup has come. File and line references were checked at commit `257afbc`.

The detailed steps and all findings are in [aufraeumen/PLAN.md](aufraeumen/PLAN.md) and [aufraeumen/BEFUNDE.md](aufraeumen/BEFUNDE.md), both in German. IDs such as `EVAL-1` refer to the findings list. That folder is removed in P7.4 and stays available in the Git history.

**Work order for AI assistants:** "Run step Px.y. Change only the named files." The rules are in [AGENTS.md](../AGENTS.md).

## Purpose

GWD trains a CNN to detect gravitational wave chirps in noise and evaluates it with ROC metrics. It also includes interactive learning apps. There is currently no valid Matched Filter baseline (see D5).

The workflow is: fetch noise → generate data → validate → train → evaluate → optimize thresholds → compare models.

## Components

The target is one installable package, `gwd`, in `src/gwd/` (D8).

| Component | Target | Responsibility |
|---|---|---|
| config | `src/gwd/config.py` | Project root, paths, and constants. Nothing happens on import; writers call `ensure_dirs()` first. |
| core | `src/gwd/core/` | Physics: waveforms, noise, SNR, interferometer learning model, time domain simulator. No file or network access. |
| data | `src/gwd/data/` | Scenarios, the one injection, the one filter chain, GWOSC access, dataset writing, provenance (manifest), and validation. |
| registry | `src/gwd/registry.py` | The one place that finds, selects, and loads models. Metadata and per-model thresholds. |
| training | `src/gwd/training/` | Model definition and training. |
| evaluation | `src/gwd/evaluation/` | Fixed test sets, metrics, thresholds, comparison, leaderboard. |
| apps | `src/gwd/apps/` | GUI, interaction, and audio only. No physics, injection, filtering, or model search of their own. |
| cli | `src/gwd/cli.py`, `src/gwd/env.py`, `main.py` | Dispatch only. `main.py` is a thin menu. |

`core/interferometer.py` and `core/simulation.py` stay in core on purpose. Whether app-specific physics belongs there is a design question (`APP-14`), and the import rules below keep the boundary.

Before the cleanup, the scripts in `src/` found each other through `sys.path` edits with generic top-level names such as `config` and `utils` (`hygiene:HYG-M5`). Since P2.1, tests and scripts both import `gwd.core` (`CORE-5`). From P2.3 to P2.6, the root `config.py` was only a shim for `gwd.config`. Since P2.4, `gwd.data` and `gwd.training` use absolute imports without `sys.path` edits and run with `python -m`, for example `python -m gwd.data.generate`. Since P2.5, all code is in `src/gwd/`: evaluation, apps, and `gwd.data.preprocessing` import absolutely, `src/utils/` is gone, and `src/gwd` has no `sys.path` edits. Since P2.6, the root `config.py` shim and the pytest `pythonpath` entries (`src` and `.`) are gone. Tests import the installed `gwd` package (editable in `.venv`, `pip install -e` in CI), so the old top-level names `config`, `utils`, `dataset`, and `gwd_core` no longer resolve.

**Model registry (since P3.3).** `gwd.registry` is the only model search. `list_models()` returns the `.keras` files in `models_registry/`, oldest first, ordered by the timestamp in the name `gwd_model_YYYYMMDD-HHMMSS`. Before P3.3 the four copies chose by ctime, which changes on chmod, copy, or restore under Linux and WSL (`apps:APPX-4`). On the laptop, ctime picked `gwd_model_20251124-234359` as the newest; the name picks `gwd_model_20251205-232013`. Names without a valid timestamp fall back to mtime with a warning. `resolve()` turns `latest`, a model name, or a path into a file, and `load_model()` imports TensorFlow lazily and loads with `compile=False`, which also avoids Keras' optimizer warning. `read_metadata()` and `write_metadata()` handle the `.json` file next to a model; training names its `.json` with `metadata_path()` since P3.7 and writes it through `write_metadata()` since P4.1. `gwd eval run` and `gwd eval thresholds` take `--model` (default `latest`), and `gwd eval compare` takes it repeatedly (default: all models). The Glitch Hunter loads its model through the registry too (`--model`, default `latest`); since P4.4 it starts without one, with 'Ask AI' off (`APP-8`). Since P4.1 it also reads the model's metadata and warns, on the console and in red above the plots, if the real noise share of its training data was 0 (`apps:APPX-1`); for metadata without the share (all models trained before P4.1) it prints a note that it is unknown. No evaluation module and no app imports TensorFlow itself: `tests/test_architecture.py` checks the source, and `tests/test_registry.py` checks at runtime that `run()` of the three evaluation modules handles an unknown model with exit code 1 without loading TensorFlow.

**Command line (since P3.6).** `gwd` (`[project.scripts] gwd = "gwd.cli:main"`) is the one entry point (D8):

| Command | Runs |
|---|---|
| `gwd data fetch-noise [--detector --gps --duration]` | `gwd.data.fetch_noise.fetch_and_slice` (network; overwrites chunks of the same name in `data/noise_background/`) |
| `gwd data generate [--n --seed --out --scenario --overwrite]` | `gwd.data.generate.generate_dataset`; `--scenario` is `train_v1` (default), `eval_v1`, or `app_v1`; a folder that is not empty needs `--overwrite` |
| `gwd data validate [--data --plots]` | `gwd.data.validate.run`; `--plots` with or without a folder writes the report plots, which are off by default |
| `gwd train [--data --epochs --batch-size --lr --patience --mixed-precision --deterministic --seed]` | `gwd.training.train.train(TrainConfig(...))` with only the options that were given; without `--seed` a seed is drawn (P5.6) |
| `gwd eval run [--model --real/--no-real --seed]` | `gwd.evaluation.evaluate.run`; since P4.3 `--no-real` is the default and `--real` adds the field test (network, D10) |
| `gwd eval thresholds [--model --save/--no-save --seed]` | `gwd.evaluation.thresholds.run`; saves by default and never asks (`EVAL-17`) |
| `gwd eval compare [--model ... --seed]` | `gwd.evaluation.compare.run` |
| `gwd eval leaderboard` | `gwd.evaluation.leaderboard.show` |
| `gwd app waveform\|interferometer` | the app module's `__main__` block, through `runpy` |
| `gwd app glitch-hunter --model latest` | `gwd.apps.glitch_hunter.app.main(model)` (since P4.4); `--model` defaults to `latest`, and with another app it exits with 2 |
| `gwd env` | `gwd.env.main`: versions, extras, waveform backend with the PyCBC version, resolved paths, matplotlib backend and whether it can open a window |

`gwd.cli` holds only dispatch. Each handler imports its module when it runs, so `gwd --help` and `build_parser()` load no numpy, and `gwd data generate` loads neither TensorFlow nor gwpy (`tests/test_cli.py`). For the `eval` commands, `--seed` calls `seed_everything(seed)`, which seeds Python's `random` and the global numpy RNG. Since P4.1, `gwd data generate` passes the seed to `generate_dataset(seed=...)`, which draws from `np.random.RandomState(seed)` (the same samples as the seeded global RNG), and `gwd train` passes it in `TrainConfig.seed`, which `train()` sets with `tf.keras.utils.set_random_seed` (Python, numpy, and TensorFlow) and gives to the split; both record it. Without `--seed`, `gwd data generate` and the eval commands are unseeded, as before; since P5.6 `gwd train` draws a seed instead, prints it, and records it with `seed_drawn: true`. Since P5.3 `gwd.core` draws only from an `rng` it is given; `gwd.data.injection` passes on its own `rng`, which defaults to the global `np.random`, so `seed_everything` still reaches the eval test sets until P5.7 passes an `rng` down. Exit codes: 0 on success, 1 when a command fails (since P5.2 also a missing PyCBC for a command that draws waveforms; unknown or missing model, missing or broken dataset, a dataset with validation findings, an output folder that is not empty, rejected or failed download, no model to compare), 2 for invalid arguments and (since P4.5) for an app that cannot open a window, 130 on Ctrl+C. Since P4.1, `gwd train` checks for `labels.csv` before it imports TensorFlow and reports a missing dataset in one line on stderr instead of a traceback; `gwd data fetch-noise` reports any download error on stderr (`DATA-6`, `tests/data/test_fetch_noise.py` lets gwpy's `fetch_open_data` raise). The modules no longer parse options: `evaluate`, `thresholds`, `compare`, `validate`, `fetch_noise`, and (since P3.7) `train` still run with `python -m` and their defaults, and stop with a pointer to `gwd` if given options. `gwd env` checks packages with `find_spec` and their metadata and imports only PyCBC, through `gwd.core.waveforms.pycbc_available()`, because only that import shows whether PyCBC works; since P5.2 it shows the backend of the pipeline (`pycbc <version>`, or `MISSING`) and of the demo apps (`pycbc` or `newton`). The smoke tests run every pipeline stage and app as a `gwd` command line (`tests/smoke/entrypoints.py`); the `python -c` drivers that set module globals and stubbed the field test are gone.

**Training (since P3.7).** `gwd.training.model.build_model(input_shape, learning_rate=LEARNING_RATE)` builds and compiles the CNN and changes no global state. Its architecture is unchanged and fixed at 1 074 609 parameters by `tests/training/test_model.py`; a new one is a deliberate change (`DATA-26`). `gwd.training.train.train(cfg)` runs one training. `TrainConfig` holds the dataset, model, and plot folders, `epochs`, `batch_size`, `learning_rate`, `patience`, and `mixed_precision`. The defaults are `EPOCHS`, `BATCH_SIZE`, `LEARNING_RATE`, and `EARLY_STOPPING_PATIENCE` in `gwd.config`, which also holds `REDUCE_LR_PATIENCE`, `VAL_SPLIT`, and `TEST_SPLIT`; the values are those hard-coded before, except the split (see below). Importing the module changes nothing (`DATA-13`): `new_run()` creates the timestamp, the name `gwd_model_YYYYMMDD-HHMMSS`, and the paths when `train()` runs, and the plot uses a matplotlib `Figure` without pyplot. Mixed precision follows D7: `choose_precision()` takes `mixed_float16` if TensorFlow finds a GPU or `--mixed-precision` is set, else float32. Before P3.7, the import set `mixed_float16` everywhere, so CPU and CI runs now train in float32; on a GPU nothing changes. `train()` prints the policy, sets it only for the run, restores the previous one, and records it as `precision_policy` in the `.json`, together with `learning_rate` and `early_stopping_patience`. Since P4.1 the `.json` also has `epochs_trained` (early stopping can end before `epochs`, the maximum), `best_epoch` (1-based, the saved weights), `seed` (null if unseeded), and from the dataset's `manifest.json` its SHA-256 (`dataset_manifest_sha256`), `dataset_scenario`, `waveform_backend`, and `real_noise_fraction`; without a manifest these four are `unknown (v1)` (`DATA-20`). The `gwd train` handler sets `TF_CPP_MIN_LOG_LEVEL=2` and `TF_ENABLE_ONEDNN_OPTS=0` with `setdefault` before it imports TensorFlow, as the module did on import before; values from the caller now win. `python -m gwd.training.train` still runs the defaults, but without those two variables.

**Training split, seeds, and metadata (since P5.6).** `gwd.training.split.split_dataset(labels, seed)` splits `labels.csv` into train, val, and test, 70/15/15 (`VAL_SPLIT` = `TEST_SPLIT` = 0.15; before, `TEST_SPLIT` = 0.2 was the validation and the test data at once, `DATA-2`, `EVAL-25`). A group is the `noise_file` of a sample; a sample with Gaussian noise is a group of its own. The groups are assigned greedily, the largest first and ties in the order of `np.random.default_rng(seed)`, each to the part that is furthest behind its share of the strata `has_signal` × `noise_source`, so each part is stratified by class and noise source and no real noise chunk is in two parts (`evaluation:MISS-4`). sklearn's `GroupShuffleSplit`, which the plan named, does not stratify and is not used. A dataset without the `noise_file` column (before P4.1) is split by sample and stratified by class, with a warning on stderr that recommends generating it again; the metadata then has `split_grouped: false`. A part that would stay empty raises `ValueError`. The module uses only numpy and pandas. `train()` seeds every run (`DATA-5`, `hygiene:HYG-M2`): `TrainConfig.seed`, or `draw_seed()` (a random integer below 2³² from `secrets`) without one, goes to `tf.keras.utils.set_random_seed` and to the split and is printed in a `Seed:` line. `TrainConfig.deterministic` (`--deterministic`) also calls `tf.config.experimental.enable_op_determinism()`, which stays on for the rest of the process; the same seed then gives the same val_loss on the CPU (checked there only; a GPU does not guarantee it). The val part steers `EarlyStopping`, `ModelCheckpoint`, and `ReduceLROnPlateau`; the test part is evaluated exactly once, with the best epoch from the checkpoint, after training. `load_data()` returns `LoadedData(X, y, labels, sha256)`: `X` is one preallocated float32 array, each sample z-scored in float64 first, so float64 datasets from before P5.6 are read the same way (`DATA-21`); `sha256` hashes the bytes of `labels.csv`, then the dtype and raw data of every sample in its order, in the same pass. The `.json` gains `dataset_hash` (that hash), `seed` (the seed used), `seed_drawn`, `deterministic`, `split_grouped`, `split` (`val_fraction`, `test_fraction`, `grouped_by`, `groups`, and the sizes `train`, `val`, `test`), `val_accuracy` and `val_loss` of the best epoch, and `test_accuracy` and `test_loss` (`DATA-20`); `metrics` keeps the values of the last epoch. `test_split` and `metrics.test_set_accuracy` are gone; neither the leaderboard nor anything else read them. Old models and their `.json` stay usable; new models are new files. The plan's optional archive without the optimizer state is not done: Keras 3 ignores `include_optimizer=False` for `.keras` files. `tests/training/test_split.py` checks sizes and class balance within ±2 % per part, that no chunk is in two parts, the warning without the column, and the seed; `tests/training/test_train.py` checks the float32 loading of float32 and float64 files, the hash, the metadata, and (slow) that two runs with the same seed and `deterministic` give the same val_loss.

**Evaluation metrics (since P4.2).** `gwd.evaluation.metrics` holds the metrics and threshold strategies as pure functions: labels and scores in, numbers out. Importing it loads neither matplotlib nor TensorFlow. `find_optimal_thresholds` moved there from `thresholds.py` and was fixed, not rewritten. Fixed FPR (5% and 1%) takes the highest TPR with FPR ≤ target, ties going to the lower FPR, and fixed TPR (90%) the lowest FPR with TPR ≥ target; before, both took the ROC point nearest to the target, which could lie beyond it (`EVAL-16`). No strategy picks the infinite first threshold of `roc_curve`, which `json` would write as the invalid `Infinity`; if no finite point meets an FPR limit, the threshold lies just above the highest score and detects nothing. F1 comes vectorized from `precision_recall_curve` (`f1_curve`) instead of one `f1_score` call per threshold, and its TPR and FPR are computed at its own threshold instead of the nearest ROC threshold. So the recommended thresholds in `results/optimal_thresholds.json` change; nothing reads them yet (P5.8). `predict_labels` is the one detection rule, score ≥ threshold, as in `roc_curve`. The operating point, the sensitivity curve, and the confusion matrix of `gwd eval run` use it; the latter two counted score > threshold before (`EVAL-15`). Since P4.3 the field test uses the same rule; the threshold stays 0.15 until P5.8. `snr_at_rate` finds SNR50 and SNR90 without the bare `except` and keeps 0.0 as a valid value, which the plot and the metrics box showed as missing before (`EVAL-22`). The metrics box shows formatted values instead of raw floats and no longer has the "False Alarms" line, which repeated the FPR; the `far` value is gone from the result, and the leaderboard never read it. `gwd eval compare` loads the models one after another, computes each ROC curve once, and gives each model one color in both panels, by sorted name; before, the bars took their colors in AUC order and the curves in load order. It writes `plot_compare_roc_<timestamp>.png` and `plot_compare_roc_<timestamp>_zoom.png`; before, the zoom overwrote the comparison plot (`EVAL-18`, `HYG-24`). The test sets are still `EVAL_V1`. `tests/evaluation/test_metrics.py` and `tests/evaluation/test_compare.py` check this; the second uses stub models, so it also runs in CI (`EVAL-20`).

**Demo apps (since P4.5).** The waveform explorer and the interferometer designer each have `build_figure()`, which returns `(fig, state)` without calling `plt.show()`; `state` is a `SimpleNamespace` with the model, the axes, the lines, and the widgets, and `main()` only shows the figure. `tests/apps/test_demo_apps.py` moves the sliders under Agg. The explorer's noise slider has its own axes name, `ax_s_noise`; as `ax_noise` it hid the noise plot, which then never rescaled (`APP-11`). The explorer no longer unpacks the unused intensity of `calculate_response` (`APP-17`); `gwd.core.simulation` keeps it until P5.4. `InterferometerModel.finesse` is a read-only property, π√R/(1−R) from `mirror_reflectivity`, about 3140 at the default R = 0.999. Before, it started at 450, and only the designer's mirror callback set it from R, so the curve jumped on the first touch of the slider, even without a change of value (`APP-12`, `CORE-11`). The finesse enters the shot noise through `cavity_gain`, so the default curve is lower where shot noise matters (1 kHz: 7.7e-23 instead of 2.0e-22), and the golden interferometer values changed in the commit `golden: finesse as a property`. The model stays a learning model (D6); P5.4 lists its ad hoc factors and replaces the invented 'LIGO Design' reference curve. The designer's feature labels are plain text, because DejaVu Sans, matplotlib's default font, lacks two of the emoji glyphs (`APP-15`). `gwd.apps._backend.require_interactive_backend()` runs first in all three apps: if the matplotlib backend is one of matplotlib's own non-interactive ones (agg, cairo, pdf, pgf, ps, svg, template), it prints on stderr what to install (Tk, or WSLg on WSL) and exits with 2. Before, the apps ended with 0 and showed no window (`apps:APPX-2`). `GWD_HEADLESS_OK=1` skips the check; the smoke tests set it. `gwd env` reports the backend through the same check. Whether a real window opens is only checked by hand.

**Glitch Hunter (since P4.4).** `gwd.apps.glitch_hunter` has three modules. `app.py` is only the GUI. `sources.py` holds the samples: `SimSource` draws through `gwd.data.injection` from the scenario of a `Mode`, 'Training' (`TRAIN_V1`, the start mode, with real noise chunks if `data/noise_background/` has any) or 'Challenge' (`APP_V1`, labelled 'hard: extrapolation': peak SNR 0.5–2, fixed 30/30 M☉, unit peak reference) (D4). `GwoscSource` picks a known event or a random H1 time in O3 (50/50), downloads it with `fetch_strain(..., pad_s=16)`, conditions it with `conditioned_crop`, as the field test does, and checks the length; a noise window keeps `DURATION + 2 * PAD_S` seconds from every event. The O3 span includes times without data, where the download fails (`APP-19`, the full O3 timeline is out of scope). `audio.py` writes the sound into a temporary folder that is removed when the window closes, plays it with `subprocess.Popen` (paplay, else aplay on Linux, afplay on macOS) or `winsound` on Windows, and reports a missing player instead of raising (`APP-9`). 'LIGO random' runs the download in a worker thread that only fills local variables and puts `(generation, sample, message)` into a `queue.Queue`; a canvas timer runs `poll_results()` in the GUI thread, which takes the newest generation over and draws it (`_render_current_sample`). Every new sample raises the generation, so a download that ends after a newer simulated sample is dropped. While it loads, 'LIGO random', 'Listen', and 'Ask AI' are locked; 'Simulation' and the mode stay usable. A failed download shows a simulated sample of the current mode and says why (`APP-5`, `APP-6`). The model is optional: `gwd app glitch-hunter --model latest` (the default) resolves it through the registry, as does a model name or path, and without a model or without TensorFlow, 'Ask AI' is off; an explicitly named model that does not exist ends with exit code 1. The threshold starts at `DEFAULT_THRESHOLD = 0.46` (D10, until P5.8), inside the slider range 0.01–0.99; an alarm is score ≥ threshold, 'UNSURE' covers the 0.10 below it, and moving the slider judges the truth box again. On real data the answer is judged too, and events outside the training masses are marked OOD (`APP-4`, `apps:APPX-3`). Without PyCBC the app starts with the simulation off and only real data; without PyCBC and gwpy it exits with 1. Importing `gwd.apps.glitch_hunter.app` loads neither TensorFlow nor gwpy. `tests/apps/test_glitch_hunter.py` (marker `apps`) drives the GUI under Agg with a dummy model and a `fetch_open_data` that waits 0.5 s; `tests/apps/test_glitch_hunter_parts.py` checks the sources, the audio, and the rating rules without a figure and runs in CI. Whether a real window survives three quick 'LIGO random' clicks is only checked by hand.

**Menu (since P2.4, gwd commands since P3.6).** `main.py` uses only the standard library. `MENU` is a fixed list of `(text, gwd arguments)` with 13 entries: the 11 from P2.5, `gwd env`, and since P4.3 `gwd eval run --real`, because `gwd eval run` alone no longer runs the field test. Each entry runs as `subprocess.run([sys.executable, "-m", "gwd.cli", ...])` in the project folder, so the menu works from any working directory and reports the real exit code. The end of input exits with 0 (after an entry, with that entry's exit code) instead of raising `EOFError`; the screen is cleared with `cls` or `clear` without a shell, only on a terminal. `tests/test_menu.py` parses every argument list with `gwd.cli.build_parser()`, so the menu and the CLI cannot drift apart. Since P4.6, `CONFIRM` maps an entry to a question and the options a yes adds: before `gwd data generate` the menu asks whether an existing dataset in `data/training/` may be replaced and adds `--overwrite` on a yes; any other answer runs the command as it is, which stops with exit code 1 on a folder that is not empty. The CLI itself never calls `input()` (`tests/test_cli.py`).

**Documentation (since P7.1).** The README describes the components, the installation per extra with the GUI backend, the workflow as `gwd` commands, the apps, the data folders and `GWD_HOME`, and the tests. `docs/evaluation.md` (moved from `ROC_ANALYSIS_README.md` with `git mv`, with the useful parts of the removed `ROC_INTEGRATION_OVERVIEW.md`) describes the evaluation commands, test sets, metrics, plots, threshold strategies, the leaderboard schema, and the baseline status. `tests/test_docs_commands.py` scans the Markdown files in the root and in `docs/`, but not `docs/aufraeumen/`: every `gwd` line in a code block and every inline `gwd` span must parse with `gwd.cli.build_parser()`, options in a synopsis such as `gwd train [--epochs --seed]` must exist on that command, `python -m` must name an importable module, `pytest -m` may use only registered markers, and every relative link must point to an existing file. So a step that changes a command also has to change the documentation.

**Project root (since P2.3).** `gwd.config` takes `GWD_HOME` if it is set and not blank, and then warns once (`Using GWD_HOME=...`). Otherwise it takes the nearest folder above `src/gwd/config.py` that contains a `pyproject.toml`, which is the repo root in the editable install. If there is none, the import fails and asks for `GWD_HOME`. Without `GWD_HOME`, all paths are the same as before P2.3 (`tests/test_config_paths.py`).

## Import rules

Since P2.6, `tests/test_architecture.py` enforces these rules. It parses every module in `src/gwd/` and `main.py` with `ast` and counts an import as lazy only inside a function body; a `try` block at module level is not lazy. The standard library is always allowed, and anything not listed under "May import" fails, so the test also limits where tensorflow, gwpy, and pycbc may appear at all. Dynamic imports (`__import__`, `importlib`) are not checked. Since P3.4, a separate check fails on any gwpy import statement outside `data/gwosc.py` and `data/preprocessing.py`, lazy or not, in any component including cli. The same test fails on any `sys.path` edit in `src/`, `tests/`, or `main.py`, and on two byte-identical `.py` files (empty `__init__.py` files excepted, `HYG-1`).

Known violations are in the test's `ALLOWLIST`, each with its finding ID and the step that removes it. An entry that no longer matches a real violation fails the test, so the list can only shrink. It must be empty by P7.4. It had 12 entries at P2.6, 8 at P3.3, 5 at P3.4, 3 at P3.6, 2 at P3.7, and 1 at P4.1. Since P5.2 it is empty: `core/waveforms.py` imports PyCBC only inside a function, when a chirp needs it (`CORE-17`).


| Component | May import | Must not import |
|---|---|---|
| config | Standard library | Any other `gwd` component, numpy, tensorflow, gwpy, pycbc, matplotlib |
| core | `gwd.core`, standard library, numpy, scipy, pycbc (lazy) | config, data, registry, training, evaluation, apps, cli, tensorflow, matplotlib, gwpy, pandas, sklearn |
| data | core, config, numpy, scipy, pandas, gwpy (lazy, only `gwosc.py` and `preprocessing.py`), matplotlib (lazy, only the validation report) | registry, training, evaluation, apps, cli, tensorflow, sklearn |
| registry | config, standard library, tensorflow (lazy, only `load_model`) | data, training, evaluation, apps, cli, matplotlib, gwpy |

**Preprocessing (since P3.2).** `gwd.data.preprocessing` has three public functions. `condition_strain(ts, fs, notches=NOTCH_FREQS, band=BANDPASS)` resamples a gwpy `TimeSeries` to `fs`, applies one notch per frequency, then the band-pass, and returns a numpy array. It is a band-pass, not whitening. It calls the methods of the series it gets and never imports gwpy itself. The noise download, the field test (through `conditioned_crop` since P4.3), and the Glitch Hunter use it; it is bit-identical to the old download chain. The field test now also notches 240 Hz, the one behaviour change of P3.2. `normalize(x, eps=1e-10)` is the z-score `(x - mean) / (std + eps)`. The eps is absolute: on conditioned strain (std near 1e-21) it dominates the std, so the field test and the Glitch Hunter pass `eps=0` there, as they had no eps before. All other callers use the default; for the synthetic test sets, which had no eps, this changes values by a relative 1e-10. Since P4.3, `conditioned_crop(ts, fs, pad_s)` runs `condition_strain` on a padded series and cuts `pad_s` off each end (see Field test below); it raises `ValueError` for a negative pad or a series not longer than both pads.

**GWOSC access (since P3.4).** `gwd.data.gwosc` is the only place that downloads from GWOSC. `fetch_strain(detector, start, end, pad_s=0, cache=True, verbose=False)` imports gwpy inside the function, calls `TimeSeries.fetch_open_data` for `[start - pad_s, end + pad_s)`, and returns the raw `TimeSeries`. It raises `StrainError` (a `ValueError`) if the sample count does not match the requested span at the series' sample rate, or if any sample is NaN; nothing is resized or padded. `pad_s=0` gives an unpadded window; the field test pads since P4.3 (see below), and the Glitch Hunter since P4.4. `cache=True` lets gwpy keep a local copy of the downloaded file (astropy's download cache), which the old calls did not. `EVENTS` is a tuple of `Event(name, gps, kind, mass1, mass2, in_training_range)` with the nine events of the old Glitch Hunter list, in the same order and with the same GPS times. The masses are rounded source-frame medians from GWTC-1 and GWTC-2, written down from the literature and not verified offline. `in_training_range` means both masses lie in the 5–100 M☉ of `TRAIN_V1` (since P3.5; before, of `generate_random_bbh_parameters`); GW170817 (BNS) and GW190814 (2.6 M☉ secondary) are out of range. The field test (`gwd.evaluation.real_data` since P4.3) picks its five events from `EVENTS` by name (`FIELD_TEST_EVENTS`, old order); a rejected download scores the event as `None` instead of an `np.resize`d window. The Glitch Hunter draws from `EVENTS` and falls back to the simulation on a rejected download instead of trimming or zero-padding. `fetch_noise` downloads its segment through `fetch_strain` and writes nothing if the download is rejected; since P4.3 it drops the first and the last chunk (see below). Importing `gwd.data.gwosc`, `fetch_noise`, `evaluate`, `real_data`, or the Glitch Hunter does not load gwpy (`tests/data/test_gwosc.py`). The download length `NOISE_FETCH_SECONDS` stays in `gwd.config`: moving it next to `START_GPS` in `fetch_noise.py` would bring back the literal 4096 that the P3.1 check forbids in `gwd.data`, and P6.3 replaces the single segment with configurable windows anyway. Tests mock `fetch_open_data` or `fetch_strain`; one real download runs only under the `network` marker, which CI never selects.

**Field test (since P4.3).** `gwd.evaluation.real_data` holds the field test, which `evaluate` ran inline before; `gwd eval run` runs it only with `--real` (D10: optional, default off), so the evaluation runs offline. `load_window(start, end)` downloads with `fetch_strain(..., pad_s=PAD_S)` (16 s), and `gwd.data.preprocessing.conditioned_crop(ts, fs, pad_s)` conditions the padded series as a whole with `condition_strain` and then cuts `pad_s` off each end. Before, each 4 s window was conditioned on its own, so the filters rang at its ends at test time only, while the training noise is conditioned in one piece (`core:MISS-2`, `EVAL-4`). Data that are too short after the crop raise `StrainError`, and the event is skipped. The noise test loads its 200 s the same way and scores the 50 windows in one batch. Events and noise windows count at score ≥ threshold (`predict_labels`). The events inside the training mass range and the OOD events (`in_training_range=False`, here GW170817) are counted separately as `EventCount(found, loaded, total)` (`core:MISS-4`); a group with a missing event reads `n/a (k of n loaded)` instead of counting it as missed (`EVAL-13`). The leaderboard column `Real_Events_Found` holds both, for example `4/4; OOD 0/1`, and `Real_Noise_FAR` holds `k false alarms in T h` instead of a rate per year from 200 s (`EVAL-21`); without `--real` both are `n/a`. The schema keeps its twelve columns until P5.8. Appending a row now reads the old rows as strings (`dtype=str`, `keep_default_na=False`); before, pandas turned `n/a` into an empty cell and `0.9000` into `0.9`. Downloads are cached by gwpy (`cache=True` since P3.4). `tests/evaluation/test_real_data.py` mocks `fetch_strain`. On synthetic noise with a 0.2–10 Hz part of std 3e-19 (raw H1 strain has a std of a few 1e-19, almost all below 10 Hz), the RMS of the first and last 0.1 s against the middle 0.1 s, pooled over 20 realizations, is 1.00 with the pad and 9.7 without. A 0.2 Hz sine of 3e-19 alone, as the plan suggested, gives no measurable edge transient, because `sosfiltfilt` extends the data with odd symmetry, so the test uses the broader low frequency part. On the real H1 windows of the five events the ratio was 1.1 to 16.6 without the pad (GW170104: 16.6) and 0.3 to 1.9 with it; real data with an event in the window are no clean test of the ratio, so these values are only a rough sign. `gwd data fetch-noise` conditions its 4096 s in one piece, so only its first and last chunk hold filter ringing; since P4.3 it writes chunks 1 to 1022 under their position in the segment and keeps all files already in the folder, naming those that are not from the new download on stderr (`evaluation:MISS-4`). The owner's existing chunks were not downloaded again. The field test results of older models change and cannot be compared with older leaderboard rows (see the PR of P4.3).

## Scenarios and SNR definition (current state, V1)

**Injection (since P3.5).** `gwd.data.injection` is the only place that draws and injects signals. `make_sample(scenario, rng=None, has_signal=None, snr=None, noise_provider=None)` returns a `Sample` with `data = noise + signal`, the noise, the scaled signal, the `InjectionParams` (masses, distance, merger time, SNR), the SNR it scaled to, and `noise_kind` (`real` or `white`). `draw_params` draws masses, then merger time, then SNR; a fixed `snr` (the sensitivity curve) is not drawn. `make_test_set` builds the normalized `(X, y)` that `evaluate`, `thresholds`, and `compare` each used to build in their own loop. `rng` is anything with the numpy `RandomState` methods and defaults to the global `np.random`, as before. Since P5.3 the module passes it to `gwd.core.noise.generate_gaussian_noise` and `gwd.core.population.random_bbh_params`; from P3.5 to P5.3 it repeated their draws itself, because `gwd.core` had no `rng` parameter. The real noise provider (`real_noise_provider`, `load_random_real_noise`) lists the chunks with `sorted(glob)` and picks one with the same `rng`, so a seed picks the same chunk on every file system; before, `random.choice` from Python's `random` module picked from an unsorted list. `Scenario.hash()` is a SHA-256 prefix of all fields that is the same in every process, unlike Python's `hash()`; `tests/data/test_injection.py` pins the three V1 hashes. A scenario with `condition_signal=True` raises `NotImplementedError` until V2. Since P4.1 a `Sample` also has `noise_file` (the chunk's file name) and `waveform_backend` (`pycbc` or `newton`; since P5.2 the `backend` argument of `make_sample` and `make_test_set`, which defaults to `gwd.config.WAVEFORM_BACKEND`), and the real noise provider returns `(noise, file name)`. A chunk that is too short or unreadable still falls back to white noise, but now warns and is recorded as white instead of real; the random stream is unchanged.

The draw order for `TRAIN_V1` was the one of the old generator, so its files were bit-identical without real noise (golden (d), and 40 samples on the PyCBC backend), and so was the sensitivity curve; since P5.3 the time axis and the dropped spin and inclination draws change them on purpose (see Core details below). The ROC, threshold, and comparison sets now draw the merger time before the SNR, and the Glitch Hunter draws the label before the noise and with `rand() > 0.5` instead of `np.random.choice`. The distributions are the same, but the same global seed gives other samples there; no seed was set before, so no stored result depended on it. `tests/data/test_injection.py` checks bit-identical batches for the same seed, also with the chunk list in reverse order, the bounds of every drawn parameter, and the V1 scale of real chunks. `test_known_skew` (`xfail(strict=True)`) asks for `TRAIN_V1` and `EVAL_V1` to draw from the same distribution and fails until V2.

**SNR definition.** The `snr` column in `labels.csv` is a peak amplitude ratio: the signal's peak divided by the noise standard deviation. It is not a matched filter SNR, so detectability at the same value depends strongly on the masses and the noise type (`data-training:SNR-DEF`, `evaluation:MISS-2`). P5.5 records `peak_snr` and `optimal_snr`.

**Provenance (since P4.1).** Two things decide what the data contains: the waveform backend, and whether `data/noise_background/` has chunks. Until P5.2 the backend was a switch in the environment too (whether PyCBC could be imported); see Waveform backend below. `gwd.data.provenance` prints the line `Backend: ... | Noise: ...` at the start of `gwd data generate` and `gwd eval run`; for a backend of `newton`, which only tests and the golden values choose, and in `generate` for a scenario with real noise but no chunks, a warning block follows on stderr. `labels.csv` has three columns after the old seven: `waveform_backend` (`pycbc` or `newton`, empty without signal), `noise_source` (`real` or `gaussian`; `noise_kind` `white` is written as `gaussian`), and `noise_file` (the chunk's file name, empty for Gaussian noise). Empty cells read as NaN in pandas unless `keep_default_na=False`. `<out>/manifest.json` holds `format`, `scenario` and `scenario_hash`, `seed`, `n`, `time_axis` (since P5.3 `arange(n)/fs`; a manifest without it was written on `linspace`), `waveform_backend` (`backend_label(backend)`, for example `pycbc 2.10.0`), `signal_backends` (signal samples per backend), `real_noise_fraction` and `real_noise_samples` (what was drawn), `scenario_real_noise_fraction`, `noise_chunks`, `noise_dir`, the versions of gwd, numpy, pycbc, and pandas, `git_commit` and `git_dirty` (null outside a Git checkout), and `labels_sha256`. It has no timestamp, so the same data from the same commit, noise folder, and working tree state gives the same manifest and hash (`tests/data/test_generate.py`). Training copies its SHA-256 into the model's `.json` (see Training above). The golden dataset values gained the three columns in a `golden:` commit; nothing else changed. `tests/data/test_generate.py` checks the columns, the manifest, the start line, and both warnings; the smoke test checks them in the pipeline and in the model's `.json`.

**Waveform backend (since P5.2).** `gwd.core.waveforms.generate_chirp(time, t_merger, backend=..., mass1=..., ...)` replaces `chirp_and_backend` and `generate_astrophysical_chirp`; it returns `(strain, frequency)`. `backend` is a required keyword, `pycbc` or `newton`, because `gwd.core` reads no config; an unknown name raises `ValueError`. The pipeline passes `gwd.config.WAVEFORM_BACKEND`, which is `pycbc`: `gwd.data.injection` (`make_sample`, `make_test_set`), `generate_dataset`, and `gwd.data.provenance`. PyCBC is imported only when a chirp is drawn (`python -X importtime -c 'import gwd.core.waveforms'` names no pycbc). A missing PyCBC raises `WaveformBackendError` with the install command for Linux and WSL, and an error of `get_td_waveform`, for example an unknown approximant, raises `WaveformBackendError` with the parameters and the PyCBC error as its cause. Before, both drew a Newton chirp with a print (and since P4.1 a warning) (`CORE-4`, `CORE-17`, `hygiene:HYG-M1`, `core:MISS-1`). `HAS_PYCBC`, `active_backend()`, and `WaveformFallbackWarning` are gone; `check_backend(backend)`, `pycbc_available()`, and `backend_label(backend)` take their place. `generate_dataset` checks the backend before it clears or writes the output folder, `gwd eval run` and `gwd eval thresholds` before they load the model, `gwd eval compare` draws its test set before it loads any model, and `gwd app glitch-hunter` checked it in the CLI handler until P4.4; since then the Glitch Hunter starts without PyCBC with its simulation off (see Glitch Hunter below). `gwd.cli.main` prints a `WaveformBackendError` on stderr and returns 1, without a traceback. `make_sample`, `make_test_set`, and `generate_dataset` take a `backend` argument; `gwd data generate` never passes it, and only the tests and `tests/golden/regen.py` pass `newton`, so the golden dataset and Newton values stay numpy-only and did not change. `TimeDomainSimulator` takes `backend` as a required keyword too. The waveform explorer (`choose_backend()`) uses `pycbc` if `pycbc_available()`, and otherwise `newton`, on purpose and in red at the top of its window: "Newton approximation, physically inaccurate: PyCBC is not installed", with the install command (default of D1; P6.1 removes the branch if D1 = A). `generate_realistic_chirp` took `backend` too until P5.3 deleted it. `tests/core/test_waveforms.py`, `tests/data/test_generate.py`, `tests/evaluation/test_evaluate.py`, `tests/test_cli.py`, and `tests/apps/test_demo_apps.py` block PyCBC with `sys.modules['pycbc'] = None`.

**Core details (since P5.3).** `gwd.core.timebase.time_axis(fs, duration, t0=0.0)` returns `t0 + np.arange(n) / fs` with `n = round(fs * duration)`; it replaces `np.linspace(0, duration, n)` in the injection, the time domain simulator, the Glitch Hunter, the validation plots, and the golden values. The spacing of `linspace` was `duration / (n - 1)`, an effective 4095.75 Hz instead of 4096 Hz (`CORE-19`, `DATA-19`), so PyCBC now draws with `delta_t` exactly 1/4096 s and new datasets differ from old ones by about 0.006 % in the sampling; `manifest.json` records `time_axis`. `generate_chirp` raises `ValueError` for a `t_merger` outside `[t[0], t[-1]]` instead of moving the merger to the edge, and its default is `t[0] + 0.9 (t[-1] - t[0])` instead of `0.9 t[-1]`, which assumed `t[0] = 0` (`CORE-15`). Its frequency is NaN where the chirp has no signal, on both backends, instead of 0. Where the window cuts a PyCBC waveform, at the start or the end, the cut edge is faded with the cosine half of a Tukey window of `TAPER_SECONDS` = 50 ms; before, the start had a 50-sample ramp whatever its comment said (`CORE-14`). The PyCBC frequency comes from the phase of h+ − i h×, so it is not meaningful edge-on (inclination π/2); the pipeline draws face-on chirps. `gwd.core.constants` holds `C`, `G`, `M_SUN`, `MPC` (the values of LAL) and `LASER_WAVELENGTH`, which the Newtonian chirp, the interferometer model, and the simulator used to repeat with rounded values; the unused `self.c` of the simulator and the `* 1.0` of the shot noise are gone (`CORE-18`). `generate_realistic_chirp`, which cut off the merger and was never called, is deleted (`CORE-1`). `gwd.core` draws only from an `rng` it is given, a numpy `Generator` or `RandomState` (`core:MISS-3`, `DATA-5`): `generate_gaussian_noise` and `generate_colored_noise` take a required keyword `rng`, so does `TimeDomainSimulator`, and the waveform explorer passes `np.random.default_rng()` or the `rng` of `build_figure(rng=...)`. `gwd.core.population.random_bbh_params(rng, masses, max_distance_mpc)` replaces `generate_random_bbh_parameters`: mass1 log-uniform, mass2 log-uniform up to mass1, distance uniform in volume up to 2000 Mpc and metadata only, no claim of 'O3' distributions; spins and the inclination are not drawn, because V1 chirps are spinless and face-on (`CORE-16`, `DATA-18`). This is an announced behaviour change: a random-mass sample draws three numbers fewer, so the same seed gives other `TRAIN_V1` merger times, SNRs, and later samples than before, from the same distributions; white noise and fixed-mass scenarios draw the same numbers. The golden Newton, PyCBC, and dataset values changed in the commit `golden: time_axis/arange, constants, and random masses without spin draws`; noise, scaling, and interferometer did not. `tests/core/test_rng.py` checks bit-identical draws for the same seed with a `Generator` and a `RandomState`, that the global numpy RNG stays untouched, and that no `np.random.<draw>(` call is left in `src/gwd/core`; `tests/core/test_timebase.py` and `tests/core/test_population.py` cover the axis and the parameter laws.

**Validation (since P4.6).** `gwd.data.validate.check_integrity(folder, on_sample=None)` returns a list of `Finding(check, message, file)`; an empty list means the dataset is intact. It checks `labels.csv` (the seven old columns, numeric values, `has_signal` in 0/1, no duplicate file names), every file it lists (exists, loads with `allow_pickle=False`, shape `(N_SAMPLES,)`, float32 or float64, only finite values, not all zeros), `sample_*.npy` files it does not list (orphans), and, if there is one, `manifest.json` against `labels.csv` (`n`, `labels_sha256`) and its scenario (known name, same `Scenario.hash()`). Before, 10 random files were loaded (`DATA-22`). `check_distribution(labels, scenario)` checks the signal samples against `signal_ranges(scenario)`, which takes the SNR, mass, and merger time bounds from the scenario's own fields (fixed masses must equal them; random masses must also have `mass2 <= mass1`), with a relative slack of 1e-9 for floats stored as text, and checks that the signal share is 50% ± 5%. Noise-only samples carry zeros and are not range-checked. This replaces the median SNR thresholds 5 and 8 and the classes up to `>20` from the old U(5,25) draw, which failed `TRAIN_V1` (peak SNR 1–12) at random (`DATA-4`, `data-training:SNR-DEF`); the same findings give the report and the exit code. A dataset without a manifest is `unknown (v1)` (`UNKNOWN_V1` of `gwd.data.provenance`, the same label the model metadata uses) and is only checked for integrity. `run()` prints the scenario, the counts per class, noise source, and backend, the min, median, and max of each signal parameter next to the scenario's range, and every finding (at most 20 per check on screen, with the rest counted), and returns 1 if there is any. The report plots are written only with `--plots`; the "SNR vs distance" panel is gone, because the distance does not change a sample with a normalized chirp (`DATA-18`), and the example samples are those with the lowest, median, and highest SNR. `gwd.training.train.load_data` calls `check_integrity` with an `on_sample` callback that z-scores each sample into one preallocated array, so the files are read once; any finding raises `InvalidDatasetError` (a `ValueError` that names the files), and `gwd train` prints it on stderr and exits with 1. Before, it skipped unreadable files and cut or zero-padded wrong lengths without failing (`data-training:LOAD-SILENT`). The samples were float64 until P5.6; since then `generate_dataset` stores them as `SAMPLE_DTYPE` = float32 of `gwd.config`, 65 536 bytes of data per file, drawn in float64 as before, so `labels.csv` is unchanged and only golden (d) `first_samples` changed (commit `golden: float32`; `DATA-21`). `generate_dataset(..., overwrite=False)` calls `prepare_output_folder` first: a missing or empty folder is used, any other raises `OutputFolderError` (exit code 1); with `overwrite=True` (`--overwrite`) only the folder's own `sample_*.npy` files and `labels.csv` are removed, not other files, not subfolders, and the new `manifest.json` replaces the old one when the dataset is written. The noise folder itself is refused as output. `tests/data/test_validate.py` covers each finding, the ranges, and the exit codes (also five seeds of 64 samples with rc 0); `tests/data/test_generate.py` and `tests/training/test_train.py` cover the folder rule and the loading.

**Known skews:**

- The evaluation SNR range lies mostly below or at the edge of the training range (`DATA-1`, `EVAL-1`).
- Training uses up to 80% real, bandpass-filtered noise, while simulation evaluation uses 100% white noise (`EVAL-2`, `data-training:NOISE-SKEW`).
- Evaluation uses only 30/30 M☉, while training uses random masses (`EVAL-3`).
- The Glitch Hunter's simulation produced data outside the training distribution (`APP-2`). Since P4.4 its start mode 'Training' draws from `TRAIN_V1`; only 'Challenge' draws from `APP_V1`, on purpose and marked as hard.
- The peak SNR refers to the measured noise std in training, but to a nominal std of 1 in evaluation and the Glitch Hunter. For white noise of 16384 samples the measured std is within about half a percent of 1; for real chunks the scale skew below applies.
- Real noise is filtered, but the signal is added unfiltered. V2 injects first and then conditions both together.
- Real noise chunks reach the CNN at a much smaller scale than white noise. `generate` normalizes the raw chunks (std near 1e-21) with the default eps, which dominates, so their std is about 1e-11 instead of 1. `train` normalizes again with the same eps. For the 1024 local chunks, the noise-only inputs end up with a std of 0.07–0.21, against 1.0 for white noise. Measured in P3.2 and kept as V1.
- The noise source is a switch in the environment (`hygiene:HYG-M1`): missing chunks still mean white noise. Since P4.1 it is printed and recorded (see Provenance above). The waveform backend no longer is a switch since P5.2: without PyCBC the pipeline stops.
